# 0. 제일 먼저: 지금 문제가 무엇이고 무엇이 달라져야 하는가

| 증상 (현재) | 원인 후보 | 반드시 바뀔 결과 |
|---|---|---|
| 점프가 낮고 무의미해 보임 | v1 `jumpVelocity=-430`, `gravity=1250` → 점프 최고 높이 약 `74wu` | **최고 높이 약 200wu**, 캐릭터 키의 3~4배 가까이 솟구쳐 건물에 도달하는 느낌 |
| 가드가 어색함 | 거리 기반 일괄 밀어내기(`+85wu`)만 적용, 접촉 연출·접촉면 고정 없음 | **몸/무기와 건물의 밑면이 실제로 붙음 → 0.10~0.15초 버팀 → 눈에 보이는 힘으로 밀어 올림** |
| 공격이 밋밋함 | 타격 판정과 검광·균열·파편·소리의 싱크 약함 | 입력 즉시 **검격, 충돌, 소재 반응, 위쪽 잔여 건물의 반동**이 동기화 |
| 층 파괴가 가볍거나 가짜처럼 보임 | 층 이미지 삭제만 수행, 파편과 구조의 인과관계 약함 | **한 레인 약점 명중 → 그 층 전체가 절단·폭파·분해 → 남은 건물이 떨어짐**이 즉각 읽힘 |
| 연타해도 박진감이 없음 | 모든 타격이 똑같고 콤보·사운드·속도에 변화 없음 | **연속 공격 리듬, 점점 커지는 타격 반응, 위기→구원→폭발의 감정 곡선** |
| 후반이 지루하거나 억지로 어려움 | 속도 수치만 상승, 템포 변주 부족 | **빠르되 읽을 수 있는 텔레그래프**, 위험한 순간의 반격, 시원한 보상 |

**최우선 결과:** 단순히 화면이 화려해지는 것이 아니다. `입력` → `몸의 반응` → `건물과의 물리적 접촉` → `파괴 판정` → `시각·음향 피드백`의 원인과 결과가 **하나의 연속 행동**처럼 느껴져야 한다.

# 1. 기존 게임 보존/변경 범위 및 패치 규칙

## 1.1 변경하지 말 것

- 3레인 이동 / 건물 한 채씩 낙하 / 최하층부터 공격 / 층의 좌·중·우 레인별 HP / **어느 한 레인 HP를 0으로 만들면 그 층 전체 파괴**.
- 공격 `Z/J`, 필살기 `X/K`, 점프 `↑/W/Space`, 가드 `↓/S`, 좌우 이동. 모바일 터치도 동일 기능.
- **목숨 3개**, 콤보, 점수, 가드 자원, 필살기 게이지, 게임 오버 및 재시작.
- 지상 가드 **콤보 초기화**, 공중 가드 **콤보 유지**라는 전략적 차이.
- 랜드마크·스프라이트·층 세그먼트·xAI 정적 에셋 파이프라인.
- 브라우저에서 로컬로 처리하는 게임, 하나의 정적 HTML 페이지, 프레임레이트 독립적인 로직.
- 게임 규칙상 **바닥 접촉 위험 판정**은 유지하되, 시각적 접촉 위치와 판정 우선순위는 본 문서대로 정렬한다.

## 1.2 값/동작 변경 우선순위

1. `점프 물리`: v1 낮은 점프값 완전히 교체.
2. `가드`: 순간 `bottomY -= 85` 또는 `bottomY -= 35` 삭제. **접촉 상태기계 + 정지 + 애니메이션된 반발**로 교체. **밀어내기 최종 총량 85wu / 35wu는 유지**.
3. `층 제거`: 논리적으로 즉시 제거하되, 잔해·절단·부서지는 소리·상단 건물 움직임 추가.
4. `공격`: 빠른 입력 판정 유지하면서 anticipatory pose/회복 프레임을 **판정 후 시각 연출**로 처리. 선딜레이로 공격을 답답하게 만들지 말 것.
5. `카메라·타격 정지·오디오·콤보 축하`: 저비용·시간 제한된 효과로 신규 추가.

**중요 충돌 해결:** 기존 문서의 `가드 접촉 시 위로 85/35wu`는 **최종 총 이동거리**를 의미하게 바꾼다. 한 프레임 순간이동을 의미하지 않는다.

## 1.3 기존 코드를 반드시 먼저 점검

- 현재 `world height=600`, 플레이어 발 바닥 좌표, 머리/무기 접촉 높이, 건물 `bottomY` 정의를 식별.
- `jumpVelocity`, `gravity`, `groundY`, `player.y`, `isGrounded`, `guardHeld`, `guardCooldown` 등 기존 필드와 충돌하는 다른 이름/로직 조사.
- `requestAnimationFrame` 호출이 중복되는지, 타격 콜백/파티클/UI 콜백이 리렌더마다 여러 개 누적되는지 확인.
- 타격에 의한 **건물 논리 좌표** 및 시각 좌표를 완전히 별도 관리하는지 확인.
- `activeFloor` 제거 시 `bottomY`가 제거된 세그먼트 높이만큼 위쪽으로 갱신되는 기존 동작 보존.
- `guardHeld`을 누르는 것만으로 건물이 미리 떠오르거나 멀리서 밀려나는 가짜 가드가 있는지 제거.
- 실제 정면 건물 사진 한 장을 단순 fade-out으로 없애는 코드가 있다면 세그먼트 아트 분리·마스킹을 사용하도록 교체.

# 3. 높이 점프 — 지금 가장 먼저 고칠 문제

## 3.1 v1이 왜 낮은가 (기존 코드와 수치 대조)

v1 값:

```txt
jumpVelocity = -430 wu/s
gravity      = 1250 wu/s²
maxHeight    = (430²)/(2*1250) = 약 74wu
```

600wu 높이 월드에서 74wu는 **화면 세로의 약 12%**에 불과하다. 캐릭터가 위층을 향해 솟아오르는 액션이 아니라 짧은 제자리 점프처럼 느껴지기 쉽다.

## 3.2 v2 물리: 가볍게 날아오르되 낙하는 재빠르게

```js
export const JUMP_FEEL = {
  jumpVelocity: -820,         // 위 방향 음수 (wu/s)
  gravityAscending: 1650,     // 상승 중 (wu/s^2)
  gravityDescending: 2600,    // 하강 중 - 좀 더 빠름 (wu/s^2)
  jumpCutVelocityFactor: 0.56,// 점프 버튼을 짧게 놓으면 높이 제한
  jumpCutWindow: 0.20,        // 이 시점 이전 release이면 short hop
  coyoteTime: 0.09,           // 방금 착지선에서 벗어난 직후도 점프 허용
  jumpBuffer: 0.11,           // 착지 직전 눌린 점프 기억
  landingSquashTime: 0.10,
  takeoffStretchTime: 0.10,
  apexFloat: 0,               // 정점에 인위적인 멈춤을 주지 않음
};
```

**이론상 풀 점프 높이:** `820² / (2×1650) ≈ 204wu` (월드 세로의 34%).  
**정점까지:** `820/1650 ≈ 0.497초`.  
**정점에서 바닥으로:** `sqrt(2×204/2600) ≈ 0.396초`.  
**총 체공:** 약 `0.89초` (충돌/가드 개입 없는 경우).

### 구현 요구

1. 키를 **길게 누르면 풀 점프**, 짧게 누르고 떼면 short hop. 풀 점프를 위해 1초간 누를 필요는 없다. 
2. `jumpVelocity`는 첫 입력 틱에 즉시 반영. 이륙 애니메이션 때문에 실제 상승을 100ms씩 지연시키지 않는다.
3. **상승/하강 중력 비대칭**: 솟는 순간 빠르고 높으며, 정점 이후 신속하게 내려온다. 물 위를 떠다니는 느낌 금지.
4. 점프 중 `Z` 연타 가능, 가드도 가능. 점프 때문에 공격 입력을 소실하지 말 것.
5. 근처 건물 밑면에 접근 시, 플레이어가 무작정 건물 이미지 안으로 뚫고 들어가지 않도록 **가드/공격/위험 접촉 우선순위**와 시각적 피벗 보정.
6. 한 번 점프로 화면 외부로 사라지지 않게 top clamp를 적용하되, 최고 높이 `204wu`를 강제로 74wu로 깎지 말 것. 배경/카메라 구성부터 확보한다.
7. 플레이어 그림자가 지면에 남아 높이를 알려준다. 상승 시 작은 그림자, 착지 시 커지는 그림자, 점프 후 바닥의 먼지.
8. 모바일 터치에서는 1회 탭 short hop, 홀드 full jump가 가능. 모바일 long press가 선택/텍스트 콜아웃을 띄우지 않게 처리.

### 코드 예시 — 고정 타임스텝 기준

```js
function startJump(player) {
  if (!player.canJump) return;
  player.vy = JUMP_FEEL.jumpVelocity;
  player.isGrounded = false;
  player.jumpElapsed = 0;
  player.jumpCutApplied = false;
  emit('JUMP_START', { x: player.x, feetY: player.feetY });
}

function updateJump(player, input, dt) {
  if (player.contactState === 'GUARD_HOLD') return; // 가드 브레이싱 중만 별도 관리
  if (player.isGrounded) return;

  player.jumpElapsed += dt;
  if (!input.jumpHeld && player.vy < 0 &&
      player.jumpElapsed <= JUMP_FEEL.jumpCutWindow &&
      !player.jumpCutApplied) {
    player.vy *= JUMP_FEEL.jumpCutVelocityFactor;
    player.jumpCutApplied = true;
  }

  const g = player.vy < 0
    ? JUMP_FEEL.gravityAscending
    : JUMP_FEEL.gravityDescending;
  player.vy += g * dt;
  player.feetY += player.vy * dt;

  if (player.feetY >= player.groundFeetY) {
    player.feetY = player.groundFeetY;
    player.vy = 0;
    player.isGrounded = true;
    emit('LAND', {});
  }
}
```

**보충:** coyote time/입력 버퍼는 기존 엔진의 이동/접지 방식에 맞게 통합한다. 3레인 아케이드에서 지면 이탈 개념이 없다면 **coyote time은 생략 가능**하나 `jumpBuffer`는 남겨 조작을 부드럽게 만든다. `jumpCutWindow`가 끝나도 버튼을 일찍 놓았을 때 별도의 점프 유지력 문제가 생기지 않아야 한다.

## 3.3 점프 애니메이션은 위치 보간이 아니라 몸 반응이어야 함

| 시점 | 캐릭터 | 주변 환경 | 피드백 |
|---|---|---|---|
| 이륙 직전 0~30ms | 살짝 웅크림, 무릎 굽힘 | 바닥 먼지·그림자 압축 | 작은 둔탁한 발구름 |
| 30~100ms | 상체 신장, 팔/무기 뒤로 | 바닥 먼지 방사 | 짧은 상승 whoosh |
| 상승 중 | 전신이 공중으로 높이 올라감 | 바람선·잔상 1~2개 | 이륙 궤적 |
| 정점 ±50ms | 몸의 회전은 작게, 무기 자세 정리 | 그림자 가장 작음 | 아주 짧은 무게감 변화 |
| 하강 | 하체가 먼저 떨어지고 상체가 따라옴 | 하향 속도선 | 추락하는 듯한 속도감 |
| 착지 0~100ms | 0.85배 높이 squash → 원상복귀 | 발 주위 먼지 | 실제 착지음 + 미세 흔들림 |

- 애니메이션이 느려도 물리 위치는 즉시 이동한다.
- **캐릭터가 위로 높이 솟아오르는 장면이 가장 먼저 육안으로 인지**되어야 한다.
- 레인 이동은 현재 월드 y를 유지하며 공중에서 자연스럽게 가능.
- 캐릭터 sprite에 별도 포즈가 없으면, Canvas에서 부분 스켈레톤/피벗 transform을 적용한다. 단일 스프라이트 전체 scale만 반복해 고무줄처럼 보이는 것은 피한다.

# 4. 가드 — 사용자 요구의 핵심: '딱 붙어서 잠깐 버티고 밀어 올리기'

## 4.1 원하는 장면을 프레임 단위로 명확히 정의

**정답은 다음 흐름이다.**

```txt
건물이 내려온다
    ↓
캐릭터가 가드 자세를 취한다 (팔/무기 위로)
    ↓
건물 밑면과 캐릭터의 가드 접촉면이 '정말로 닿는다'
    ↓
쿵! / 몸이 3~4wu 눌리면서 건물이 정확히 그 자리에서 0.12초 멈춘다
    ↓
캐릭터가 몸에 힘을 주고 밀어 올린다
    ↓
건물이 0.16~0.21초 동안 실제로 위로 반동한다 (공중 35wu / 지상 85wu)
    ↓
반발이 끝나면 낙하속도가 자연스럽게 되살아나 다시 떨어진다
```

**절대 금지:**

- 접촉 전 건물과 캐릭터 사이가 40~80wu 떨어져 있는데 갑자기 건물이 위로 점프함.
- 가드 버튼을 누르기만 해도 먼 건물이 멈춤.
- 가드 성공 시 `building.bottomY -= 85` 한 줄로 순간이동.
- 가드 때 캐릭터가 건물 내부로 들어가거나, 오히려 둘 사이가 눈에 띄게 벌어진 채 버티는 연출.
- 건물 밑면과 머리/무기가 겹치거나, 한 프레임에 좌표가 흔들리는 접촉 떨림(jitter).
- 정지 시간이 늘어져 게임 전체가 0.5초씩 멈춰 버리는 가드.

## 4.2 히트박스와 가드 접촉면을 따로 설정

3레인 게임에서 **가드는 플레이어 현재 레인의 건물 밑면을 받치는 행동**이다. 가드 접촉점은 눈에 보이는 손/검/방패의 최상단에 있어야 한다.

```js
function getPlayerGuardPlaneY(player, pose) {
  // 아래로 갈수록 +Y인 월드 좌표
  return player.feetY - player.height - pose.guardReachAboveHead;
}

const GUARD_FEEL = {
  guardReachAboveHead: 8,  // 캐릭터 머리보다 접촉 자세가 8wu 높음
  contactLookAhead: 16,    // 16wu 이내까지 접근할 때 접촉 후보
  maxSnapCorrection: 7,   // 그 이상 순간적인 위치 보정 금지
  braceCompression: 4,    // 쿵 하는 순간 무릎/어깨 눌림
  braceCompressionMs: 35,
  holdMs: 120,
  repelGroundUnits: 85,
  repelAirUnits: 35,
  repelGroundMs: 210,
  repelAirMs: 160,
  releaseBlendMs: 80,
  contactCooldownMs: 280,
  contactGraceMs: 70,     // 방어 입력과 실제 접촉 사이의 보정 허용
};
```

### 접촉 규칙 (중요)

- `gap = playerGuardPlaneY - building.bottomY` (양수면 건물이 캐릭터 위에 떨어져 있는 중).
- `gap > 16wu`: 가드 자세를 준비하지만 **건물 논리 좌표와 낙하속도는 변경하지 않는다**.
- `0 <= gap <= 16wu`에 진입할 때 정확한 교차 순간을 swept collision으로 계산해 `CONTACT_HOLD` 시작.
- `gap < 0`으로 이미 약간 겹쳤다면 기존 프레임/입력 순서로 생긴 **작은 수치 오차 한도(≤7wu)**에서만 위치 보정 허용. 깊이 관통이면 이미 실패한 충돌이므로 가드로 멀리 순간이동시키면 안 됨.
- 건물 밑면을 `contactPlaneY`에 고정하고, 캐릭터의 상향 무기/가드 자세를 접촉점에 그린다. 시각 효과의 스파크 좌표도 **이 접촉점**이어야 한다.
- 플레이어가 공중에 있다면 120ms 버티는 동안 **캐릭터와 건물의 상대 거리**가 벌어지지 않게 플레이어 수직 물리를 잠시 브레이싱 상태로 묶는다. 이때 `preGuardVy`를 저장한 뒤 해제 시 정상 물리로 부드럽게 복귀한다.
- 가드 입력 직후 건물과 멀리 떨어진 경우, **건물을 끌어당겨 맞닿게 하지 않는다**. 실제로 닿을 때까지 준비 포즈만 유지한다.
- 건물의 낙하 예상 이동량이 프레임당 접촉 허용 범위보다 클 경우 **연속 충돌 검사(swept contact)**로 터널링을 방지한다.

## 4.3 가드 상태기계 (별도로 구현)

```txt
GUARD_OFF
  ├─ guard button pressed, has resource → GUARD_READY
  └─ otherwise → GUARD_OFF

GUARD_READY
  ├─ close and swept contact → GUARD_HOLD
  ├─ released / window expired / no energy → GUARD_OFF
  └─ no contact → GUARD_READY (건물에는 힘 미적용)

GUARD_HOLD (접촉점에 붙고 120ms 버팀)
  ├─ after 120ms → GUARD_REPEL
  └─ cannot retrigger contact

GUARD_REPEL (눈에 보이는 방향으로 밀어 올림)
  ├─ after 160~210ms → GUARD_RELEASE
  └─ cannot retrigger contact

GUARD_RELEASE (속도 자연 복귀, 80ms)
  └─ finish → GUARD_COOLDOWN → GUARD_OFF

GUARD_BREAK (자원 소진/조건 실패)
  └─ 충돌이 실제 발생할 경우에만 페널티 → GUARD_OFF
```

**구현 최우선 판정:** `필살기 무적 → 유효 가드 접촉 → 위험 충돌 → 라이프 감소`. 동일 프레임의 접촉과 실패 판정을 동시에 실행해 목숨이 사라지면 버그.

### 상태별 동작 테이블

| 상태 | 건물 `bottomY` | 건물 속도 | 캐릭터 | 시각/음향 |
|---|---|---|---|---|
| `GUARD_READY` | 원래 낙하 | 원래 낙하 | 즉시 방어 자세 | 무기 올림, 작고 긴장된 빛 |
| `GUARD_HOLD` | **접촉 평면에 고정** | 0 | 몸 4wu 압축, 접촉 유지 | 둔탁한 `쿵`, 접촉 스파크, 화면 3~4px 흔들림 |
| `GUARD_REPEL` | **접촉점부터 85/35wu를 애니메이션 이동** | 계산된 상향 운동 | 팔로 밀어올리고 복원 | 짧은 충격파, 밀어내는 소리 |
| `GUARD_RELEASE` | 연속적인 물리 위치 | +Y로 부드럽게 복귀 | 지상/공중 상태 정상 복귀 | 파편·먼지 사라짐 |
| `GUARD_COOLDOWN` | 정상 낙하 | 정상 낙하 | 정상 조작 | 중복 충돌 억제 |

## 4.4 '딱 붙어 있음'의 진짜 구현: 게임 논리 위치와 그리는 위치를 혼동하지 말 것

건물 밑면을 접촉점에 맞추는 첫 순간, 그림의 맨 아래 장식/파편이 실제 히트박스보다 아래까지 나올 수 있다. **각 랜드마크의 타격용 밑면(anchor) 위치**를 명시한다.

```js
landmarkRendering = {
  contactBaseOffsetY: 0,       // 실제 건물 밑면을 그릴 때 기준점
  visualOverhang: 3,           // 장식의 가시적인 미세 돌출 (판정 무관)
  debrisSpawnFromContact: true,
};
```

- 광화문 기단, 철골 에펠탑의 다리, 건물 사진의 흰 여백 등에서도 **보이는 밑면**과 **판정 밑면**의 높이를 보정한다.
- v1처럼 사진 원본 자체에 하단 투명 여백이 남은 경우 에셋 crop/anchor를 수정한다. 코드로 임의의 큰 스냅 값을 넣지 않는다.
- `GUARD_HOLD`에서는 `contactPlaneY`를 정확히 유지하며, 렌더 시 미세 1~2px 압축 표현만 허용한다.
- 화면 흔들림은 건물과 플레이어를 **같은 카메라 공간**에서 흔들어야 둘 사이가 분리되지 않는다. HUD만 고정.

## 4.5 밀어 올리기: 순간 위치이동을 물리적으로 보이는 모션으로 교체

### 거리를 보장하면서 힘의 질감이 있는 ease-out

```js
const easeOutCubic = t => 1 - Math.pow(1 - t, 3);

function updateGuardRepel(contact, dt) {
  contact.repelElapsed = Math.min(
    contact.repelDuration,
    contact.repelElapsed + dt
  );
  const t = contact.repelElapsed / contact.repelDuration;
  const travel = contact.repelDistance * easeOutCubic(t);

  // 접촉 이후의 시작 바닥 좌표로부터 연속적으로 위로 이동.
  contact.building.bottomY = contact.startBottomY - travel;
  // release에서는 위치 연속성을 지키며 낙하속도로 복귀한다.
}
```

**경고:** 기존 `updateFallingBuilding()`이 같은 틱에 `bottomY += speed*dt`를 실행하면 위 코드의 애니메이션과 충돌한다. **건물의 Y 좌표를 쓰는 소유권은 상태당 단 한 곳에만** 있어야 한다.

- `GUARD_HOLD`와 `GUARD_REPEL` 동안 기본 낙하 적분을 **중지**.
- `GUARD_RELEASE` 시작점의 `bottomY`를 저장하고, 첫 프레임부터 정상 낙하로 전환. 속도는 0부터 목표 낙하속도까지 `80ms` 보간하여 불연속성 제거.
- 반발 거리가 실제로 누적 `85/35wu`인지 확인. 구 애니메이션/이펙트에서 별도 위쪽 반동을 또 더하지 않는다.
- 접촉 중 공격 입력이 들어오면 마지막 1개를 `≤100ms` 버퍼링해 밀어내기 시작 직후 연결. 가드 애니메이션 때문에 키 입력이 사라지지 않게 한다.

## 4.6 가드 성공 연출을 세 단계로 나누기

**A. 첫 접촉 0~35ms**
- 캐릭터가 상체를 웅크리며 팔을 위로 받친다. 손/무기 끝이 건물 밑면에 정확히 닿는다.
- 건물은 **그 자리에서 멈춘다**. `CONTACT!` 등 텍스트는 선택 사항이고 크지 않게.
- 접촉점 중심 **방사형 짧은 번쩍임 + 스파크 6~10개**, 한 번뿐인 낮은 둔탁한 타격음.
- 아주 미세한 접촉 압축(캐릭터 포즈 4wu). 플레이어와 건물 실제 히트박스가 벌어지지 않는다.

**B. 버티는 순간 35~120ms**
- 캐릭터 몸/팔에 약한 떨림. 건물은 바닥에서 눈에 띄게 **정지해 있음**.
- 빛나는 접촉선이 매우 짧게 유지. 무기/팔/머리가 건물 속으로 파묻히지 않는다.
- 화면을 완전히 멈추지 않는다. 배경의 먼지와 캐릭터 표정·몸떨림은 여전히 움직일 수 있음.

**C. 밀어내기 120~330ms(지상), 120~280ms(공중)**
- 지상: 캐릭터가 다리로 지탱한 다음 위로 `쿵!` 밀어 올리며 건물이 총 85wu 반발.
- 공중: 공중에서 방향을 바꾸는 짧은 검격/충격파로 총 35wu 반발.
- 접촉면에 균열/먼지 분출, 파편 작은 조각 떨어짐, 캐릭터 반동 애니메이션.
- 가드 성공 직후 **0.35초 이내 공격 시** 별도의 `COUNTER!` 텍스트/색감(상태표시용, **추가 무상 데미지 없음**) 선택 도입.

### 지상/공중 차별화 (기존 규칙 유지)

| 항목 | 지상 | 공중 |
|---|---|---|
| 가드 게이지 | v1에 정의된 비용 유지 | v1 비용 유지 |
| 콤보 | 0으로 리셋 | 유지 (+기존 타이머 연장) |
| 버팀 | 120ms | 110ms 내외 가능 |
| 상승 거리 | 85wu / 210ms | 35wu / 160ms |
| 사운드 | 중저음 `THUD` + 건물 긁힘 | 얇고 빠른 `CLANG` + 바람 |
| 화면 흔들림 | 3~4px | 2~3px |
| 자세 | 무릎 압축/손으로 받침 | 공중에서 전신 회전/무기 받침 |

## 4.7 누른 채 버티기/연타 악용 방지

- 가드 시작 시 v1의 가드 윈도우 0.25초를 기준으로 접촉을 기다린다. 이후 **유효 접촉이 없으면 건물을 건드리지 않는다**.
- 성공한 접촉 이벤트 하나당 비용 **정확히 1회** 소비. 게이지 초당 유지 소모도 v1 방식대로 **중복 계산하지 말 것**.
- `GUARD_HOLD→REPEL→RELEASE` 진행 중 같은 건물 접촉 이벤트가 재발동하지 않는다. 이벤트 ID로 de-dup.
- 건물 접촉면이 다음 층으로 바뀌면 새 세그먼트 ID와 가드 쿨다운을 함께 검증.
- 게이지 부족이면 `GUARD_BREAK` 사운드/자세만 표현하고 **실제 방어 효과 없이 위험 충돌 로직을 따른다**.
- 가드 성공 연출을 틈타 필살기 입력을 무시하지 말고 버퍼를 관리하되, 상태 전환 순서는 `SPECIAL` 우선.

# 5. 공격: '칼을 휘둘렀다'가 아니라 '거대한 구조물을 베었다'

## 5.1 공격 1회는 다음 5가지가 같은 지점에서 발생해야 한다

1. **캐릭터 동작:** 칼/무기를 휘두르는 방향 변화, 상체 회전, 발 지지.
2. **칼날 흔적:** 빠르고 밝은 곡선형 검광, 미세 잔상.
3. **충돌 지점:** 실제로 때린 레인과 최하층에 1프레임 이내로 스파크/균열.
4. **건물의 반응:** 타격 부위의 흠집 + 미세한 건물 흔들림/관성.
5. **청각:** 휘두르는 소리 + 맞았을 때 재질에 맞는 타격음.

이 5개가 분리되어 보이면 공중에 칼을 휘두르는 느낌이 난다.

## 5.2 공격 애니메이션 구간 (각 입력에서 95ms 안팎)

| 구간 | 시각적 동작 | 판정 및 입력 |
|---|---|---|
| `0~12ms` | 몸통 회전 시작, 칼날 첫 검광 | **즉시 판정**, hit event 즉시 발행 |
| `12~40ms` | 가장 넓은 검광 원호, 충돌 스파크와 건물 요동 | hit-stop 동기화 |
| `40~75ms` | 검광 급격히 감쇠, 파편 비산 | 다음 공격 입력 버퍼 허용 |
| `75~95ms` | 다음 타격으로 연결하는 포즈 | 다음 판정 가능 |

- `95ms` 쿨다운은 **유효 명중의 기본 속도**. 성능 저하로 애니메이션이 버벅여도 입력·타격의 **게임 규칙상 간격**은 보존.
- 매번 동일한 각도로 치면 '자동 반복 GIF'처럼 보인다. 짝수/홀수 타격마다 **검격 방향·몸통 피벗·검광 궤적을 2~3종 번갈아 적용**.
- 너무 큰 검광이 다른 층/레인을 동시에 때린 것처럼 보이면 안 된다. **시각은 넓게, 논리 데미지는 현재 활성 최하층의 현재 레인에만 1회**.
- 명중하지 않으면 작은 휘두름 소리만 재생. 파편·점수·게이지·콤보를 발생시키지 않는다.

## 5.3 HP별 완전히 다른 시각 반응

| 상황 | 건물 화면 반응 | 사운드 | 게임 로직 |
|---|---|---|---|
| HP 3→2 | 깊고 짧은 흠집, 콘크리트 먼지, 소규모 스파크 | 무거운 `탁` | HP -1 |
| HP 2→1 | 균열이 크게 퍼지고 작은 조각 떨어짐, 붉거나 하얀 응력선 | `쨍/콰직` | HP -1 |
| HP 1→0 | 균열이 전 층에 전파 → **층 전체가 절단·폭파** | `콰앙 + 사각사각` | **해당 층 전체 제거** |

- HP가 높은 곳은 **'아직 버티는 재질'**, HP 1은 **'거의 깨질 재질'**로 확실히 보여야 한다.
- 이미 파괴된 층을 또 때려도 파괴 파티클·점수·콤보가 재발생하지 않는다.
- 재질별 다른 에셋/프로시저럴 효과: 유리(`SHATTER`), 석재(`CRUMBLE`), 철골(`SPARK`), 목재/기와(`SPLINTER`), 혼합(`MIXED`).

## 5.4 한 층이 파괴되는 장면: 보여주는 순서가 중요하다

```txt
T +   0ms: 약점 HP 0 판정 확정, floorCleared=true (논리에서 즉시 제거)
T +   0ms: 화면에는 마지막 히트 지점이 1프레임 강하게 번쩍임
T +  10ms: 균열이 층 너비 전체에 퍼짐 (좌→우 20~40ms)
T +  20ms: 파괴된 층이 3~6개 큼직한 절단조각으로 분리되어 바깥으로 터짐
T +  30ms: 잘게 부서지는 파편 12~26개 + 먼지 고리 + 충격파
T +  45ms: 해당 층의 기존 원본 이미지 완전히 사라짐
T +  55ms: 잔여 건물 위쪽의 미세 반동/무게 전달 표시
T +  90ms: 잔여 건물 정상 낙하·다음 층 공격에 시각적으로 완전히 연결
```

**판정 핵심:** 점수/활성층/충돌박스는 `T+0ms`에 새 상태가 된다. 분해 조각은 **충돌 불가능한 시각 객체**다. 45ms 동안 잘라낸 층의 고스트를 보여줄 수 있지만 **다시 피격할 수 있는 실제 층으로 유지해서는 안 된다**.

### 왜 큰 조각과 작은 조각을 함께 쓰나?

- 점처럼 작은 파티클만 나오는 건 '먼지'로 보이고 건물 무게가 안 느껴진다.
- 큰 조각만 튀면 실제 파괴 같지 않고 조립 블록처럼 보인다.
- **큰 단면 3~6개 + 작은 파편 12~26개 + 먼지/잔해**가 함께 있어야 층이 부서진 인과관계가 전달된다.

## 5.5 파괴된 층과 남아 있는 건물의 연결

- v1의 **논리적 `bottomY -= removedFloor.height`는 즉시 적용**한다. 새 최하층 충돌 판정도 즉시 갱신.
- 시각적으로는 위층 잔여 구조물이 갑자기 사라졌다 나타나는 것처럼 보이지 않게, **기존 스프라이트의 월드 앵커를 보존**하고 제거된 부분만 분리한다.
- 파괴 직후 위쪽 건물의 시각적 반동: **2~5wu 상향 미세 반동 / 55~85ms**, 단 **렌더 전용 offset**으로 처리 (논리 좌표를 추가 변경하지 않는다).
- 큰 구조물에서 아래층을 잘랐을 때 상부 구조가 30°로 옆으로 넘어가면 레인 판정과 그림이 어긋난다. 상부는 최대 1.0° 흔들림 후 복원, 대폭 쓰러지는 조각은 **파괴된 층의 비충돌 데브리**에 한정.
- 건물 잔여 층수 1개일 때는 **다음 타격이 곧 완파**임을 보여주되, 미리 터지거나 점수 지급 금지.

## 5.6 건물 완파 '피니시' 연출

- 마지막 층을 부수면 남은 건물 입자가 잔광과 함께 터지고, 화면 중앙 하단에 `DESTROYED!` 또는 해당 건물명 `완파!` 출력.
- **마지막 일격**은 일반 층 파괴보다 강한 저음 + 한 번의 큰 충격파. `고급 레전드 건물`일수록 색·재질은 다르게.
- 화면 흔들림은 7~9px / 120~160ms 범위 안에서 제한. 남발 금지.
- 카메라가 **0.12초만 살짝 줌인 후 복귀**하는 연출은 선택 적용. 캐릭터·건물·HUD가 흐릿해지면 비활성.
- 중요한 점: **다음 건물이 0.35~0.55초 안에 등장**, 필살기 외에는 긴 승리 컷신이 없어야 한다.

# 6. 전투가 '재미있는 게임'으로 느껴지게 만드는 핵심 연출 시스템

## 6.1 Hit-stop: 프레임 지연이나 게임 렉이 아닌 의도적 충돌 감각

| 이벤트 | 권장 정지시간 |
|---|---:|
| HP 감소 일반 타격 | 25~32ms |
| 층 전체 제거 | 45~60ms |
| 건물 완파 최종 일격 | 65~75ms |
| 가드 첫 접촉 | 가드 상태 `GUARD_HOLD` 120ms에 포함; **추가 hit-stop 중복 금지** |
| 필살기 최종 폭발 | 65~85ms |

**잘못된 방식:** `setTimeout`으로 게임 루프를 중단하거나, 60Hz 한 프레임 밖에 표현할 수 없는 25ms를 부정확하게 처리, 모든 레이어를 무조건 프리즈.

**올바른 방식:** **시뮬레이션 시간(gameplay time)**과 **연출 시간(effect time)**을 분리하고 짧은 타격 정지는 논리 업데이트 일부만 pause하는 방식.

- `rAF` 자체는 계속 돌려 카메라 진동·충격파·글로우·사운드가 보이게 한다.
- 타격 정지 중 추가 공격이 중복 판정되지 않도록 입력은 **버퍼에 1회 기록**.
- combo 타이머, 낙하 충돌 타이머도 hit-stop만큼 잠시 멈춤. 플레이어만 묶이고 건물만 내려와 불합리하게 죽는 현상 금지.
- 온라인 타이머·브라우저 실제 시간은 별도이므로, 점수/스폰 속도/게이지 쿨다운은 해당하는 게임 시간 기준으로.
- 이미 가드 상태 정지 120ms가 걸렸다면 hit-stop 30ms를 별도로 더하지 않는다.

## 6.2 타격감 스택: 최소 4가지가 같은 프레임에

```txt
hit confirmed
 ├─ ① player slash pivot / sword trail
 ├─ ② contact spark / crack / debris
 ├─ ③ 2~6px camera impulse (HUD excluded)
 ├─ ④ dual-layer audio: whoosh + actual hit
 ├─ ⑤ small enemy/building knock response
 └─ ⑥ floating score / combo text
```

**한 가지 이펙트만 크게 해서는 안 된다.** 상이한 감각을 동시에 주되 화면 가독성을 유지한다.

## 6.3 카메라 연출: 흔들리는 화면이 아니라 세기를 느끼게 하는 화면

| 이벤트 | 이동 진폭 | 지속시간 | 카메라 방향 |
|---|---:|---:|---|
| 일반 타격 | 2px | 45~55ms | 공격 반대쪽으로 한 번 |
| HP2→HP1 강한 타격 | 3px | 60ms | 타점에서 멀어지듯 |
| 층 파괴 | 4~6px | 85~110ms | 아래쪽 압력 + 좌우 반동 |
| 지상 가드 성공 | 3~4px | 80ms | 건물 아래로 묵직한 눌림 |
| 건물 완파 | 7~9px | 140ms | 폭발 방향, 감쇠 |
| 피해 | 8px 이하 | 160ms | 아래 방향 짧게 |
| 필살기 폭발 | 8~10px 이하 | 160ms | 극적인 1회 |

- 카메라 진폭은 렌더 픽셀 기준의 가이드. DPR과 캔버스 스케일을 고려하여 여러 디바이스에서 비슷하게 느껴야 한다.
- 여러 임펄스가 같은 틱 발생할 때 **상한 10px**으로 합성. 랜덤 브라운운동을 무한히 적용하는 화면 흔들림 금지.
- HUD/모바일 버튼은 흔들리지 않게 분리. 적힌 숫자를 읽을 수 있어야 한다.
- 저동작 모드 `prefers-reduced-motion`에서는 셰이크를 0으로 하거나 크게 축소한다.

## 6.4 스피드 라인 / 공격 방향 잔상

- 상승 점프 시 가늘고 짧은 **아래 방향으로 늘어지는 잔상** 2개.
- 강한 하강 시 수직 라인 3~6개. 화면 전체에 계속 뿌리지 않는다.
- 칼 휘두름 시 마지막 35~70ms의 칼끝 이동 궤적을 보간해 곡선(arc)을 그림.
- 콤보가 상승할수록 원호 너비·밝기는 약간 증가 가능하지만 **판정 범위는 절대 증가하지 않는다**.
- 레인 변경 시 캐릭터 x 위치만 75ms ease-out, 작은 움직임 잔상. 이동판정은 기존의 즉시 레인 변경 규칙 유지.

## 6.5 밀도와 템포의 대비를 만들어야 흥미진진하다

- 모든 프레임이 빛나거나 흔들리면 신호 대 잡음비가 무너진다. **기본 플레이는 선명**, 파괴 순간은 폭발적.
- 가드 정지는 고속으로 흐르던 상황을 **0.12초 잡아주는 순간**이므로 전후 속도 대비를 만든다.
- 높이 점프는 정점에서 바닥이 확실히 멀어지고, 착지 시 다시 가속하는 대비를 만든다.
- HP1 약점에 맞는 선택이 무작위 연타보다 **눈과 귀에서 확실히 더 큰 보상**을 주게 만든다.
- 게임 진행이 빠를수록 배경 풍압/낙하 와류 증가, 그러나 타격 판정이나 난이도 수식은 v1 유지.

# 7. 파편·먼지·재료별 반응: 사라지는 이미지 대신 부서지는 구조물

## 7.1 3계층 파괴 입자

| 종류 | 한 층 완파 시 개수(기본) | 크기 | 수명 | 역할 |
|---|---:|---|---|---|
| **A. 큰 조각** | 3~6 | 층 너비 8~25% | 0.45~0.85s | 실제 층의 물리적 파괴 인식 |
| **B. 작은 파편** | 12~26 | 2~8px 상당 | 0.35~0.85s | 폭발감, 속도감 |
| **C. 먼지/스모크** | 5~10 | 확산형 | 0.30~0.65s | 구조물 무게감, 잔향 |

초기 속도 예시(world units/sec):

```js
const DEBRIS_FEEL = {
  chunkSpeedX: [-170, 170],
  chunkSpeedY: [-260, -90],
  chipSpeedX: [-240, 240],
  chipSpeedY: [-310, 40],
  gravity: [820, 1250],
  angularSpeed: [-8, 8],
  chunkCount: [3, 6],
  chipCount: [12, 26],
  smokeCount: [5, 10],
  maxParticlesDesktop: 260,
  maxParticlesMobile: 140,
};
```

- 파편은 `x += vx*dt`, `y += vy*dt`, `vy += gravity*dt`, `rotation += angularSpeed*dt`로 실제 갱신.
- **잘라낸 층의 텍스처 일부**를 큰 조각에 입혀야 건물 자체가 부서져 나온 느낌이 난다. 단순 회색 네모 6개만 나오는 연출 금지.
- 파편 초기점은 **파괴된 층의 좌표**에서 생성. 캐릭터 중심/화면 중앙에서 무작위로 나오는 연출 금지.
- 큰 조각은 바닥에 닿으면 1회 가볍게 튕긴 뒤 페이드하고, 판정에는 일절 영향 없음.
- 랜드마크 원본 실루엣이 평면인 경우 프로시저럴 폴리곤 조각+UV crop으로 재질 특징 유지.
- 모바일 저사양에서는 파편 수를 줄이고 큰 조각 + 절단선은 반드시 유지. 중요한 인과관계를 지우지 말 것.

## 7.2 소재별 차별화

| 유형 | 충돌/파괴 모션 | 연출 |
|---|---|---|
| 유리 커튼월 (롯데월드타워 등) | 얇은 파편이 방사형으로 튀며 반짝임 | 고음 `찰캉 + 자잘한 유리` |
| 콘크리트/석재 (엠파이어·콜로세움 등) | 묵직한 블록 + 큰 먼지 구름 | 저음 `콰직 + 둔탁한 덜컹` |
| 철골 (에펠탑·도쿄타워 등) | 길쭉한 금속 파편 회전·충돌 | 금속성 `캉 + 쇳소리 잔향` |
| 목재/기와 (경복궁 등) | 기와 조각·목재 길쭉한 파편 | 깨지는 `타닥 + 우지끈` |
| 특수 상층부 (첨탑 등) | 좁은 세그먼트가 회전·균열 | 큰 파편 대신 특징적인 낙하 잔상 |

소재와 연출을 일치시키기 위해 세그먼트 메타데이터에 `materialType`을 추가한다. 기존 에셋 경로는 가급적 변경하지 않는다.

# 8. 콤보·점수·위기 연출: 박진감 증가, 원래 판정 유지

## 8.1 콤보가 오를수록 달라지는 건 '성취감'

| 콤보 | 화면 | 음향 | 로직 |
|---|---|---|---|
| 1~9 | 작은 숫자, 깔끔한 타격음 | 기본 | v1 점수식 유지 |
| 10~24 | `10 COMBO` 팝, 검광 색감 살짝 진해짐 | 음 높이/볼륨 미세 증가 | v1 유지 |
| 25~49 | `RUSH!`, 임팩트 팝 커짐, 화면 가장자리 속도선 | 타격 레이어 1개 추가 | v1 유지 |
| 50~99 | `UNSTOPPABLE!` 짧은 배너, 타격이 경쾌해짐 | 킥/저음이 가끔 강조 | v1 유지 |
| 100+ | `LEGENDARY!` 0.5초 이하, 배경 펄스 | 짧은 승리 스팅거 | v1 유지 |

- 팝업은 최대 1~2개만 남게 병합. 글자가 건물 약점 위를 가리지 않게 HUD 근처 배치.
- 콤보가 커져도 발광/번쩍임을 무한히 키우지 않는다. 특히 모바일 가독성.
- **가드는 지상/공중 콤보 유지 규칙이 정확히 반영되어야** 템포·위험 선택이 살아난다.

## 8.2 위험이 닥치는 순간 '반응할 이유'를 보여주기

- 건물 최하층이 가드/위험선과 **40wu 이내**가 되면, 실제 거리가 가까울 때만 캐릭터 주변에 작은 압력선/먼지 반응.
- **0.25초 안에 바닥 충돌할 것으로 예측**되면 HUD 하단에 짧은 `DANGER` 또는 두근거림 효과 1회 (중복 스팸 금지).
- 위험선에 도달하기 0.3초 전에 타격 방향으로 약점이 번쩍이는 **도움말식 과잉 유도는 초반 3채까지만** 허용. 그 후 플레이어가 직접 읽게 한다.
- 마지막 남은 목숨에서 배경/UI에 낮은 강도의 긴장감은 주되 **시야를 붉은 오버레이로 덮지 않는다**.
- 피해 직전에 성공한 가드나 필살기는 `CLUTCH!` 짧은 보상 텍스트. **추가 무상 HP/목숨 회복 없음**.

## 8.3 완파 패턴 다양화 (같은 룰, 다른 체감)

- 한 타 약점 층: 강한 `ONE HIT BREAK!` (실제 1회로 제거됐을 때만).
- 같은 위치에서 3층 이상 연속 파괴: `CHAIN CUT!` 텍스트 (추가 데미지 없음).
- 가드 직후 0.35초 이내에 공격 성공: `COUNTER!` 텍스트 (추가 데미지 없음).
- 공중에서 마지막 층 제거: `AERIAL FINISH!` 텍스트 (추가 데미지 없음).
- 필살기 완파: 전용 전방위 연출 (v1 점수 지급식 변경 없음).
- 이벤트 타입별 **중복 UI 방지 우선순위** `SPECIAL > FINISH > CLUTCH > CHAIN > COMBO > NORMAL`.

# 9. 오디오: 이펙트가 많아도 소리가 허전하면 손맛이 없다

## 9.1 필수 음원 레이어

| 액션 | 소리 구성 | 주요 감각 |
|---|---|---|
| 기본 공격 허공 | 짧은 `휙` | 속도감 |
| 공격 명중 | `휙 + 칼/표면 충돌` | 타격 위치 |
| HP1 완파 | `콰직 + 재질 파손 + 저음 킥` | 파괴되는 무게 |
| 점프 시작 | `휙 + 가벼운 발구름` | 상승 |
| 착지 | 바닥 `툭/쿵` | 중력 회복 |
| 가드 첫 접촉 | `쿵/캉` 강하고 짧게 | 붙어서 버팀 |
| 가드 밀어내기 | 짧은 `웅 + 밀어냄` | 반발 힘 |
| 필살기 | 템포 상승→찰나 정적→수직 검광→폭발 | 큰 보상 |
| 게임오버 | 짧은 하향 음계 + 충돌음 | 명확한 실패 |

### 오디오 구현 기준

- Web Audio API로 최소한 기본/특수 타격·가드·완파를 구현하거나 라이선스 확인된 로컬 파일 사용.
- 공격마다 음량·피치를 **아주 작게만 변화**(예: ±3% 피치)시켜 반복 연타의 기계성을 줄인다. 무작위 볼륨 폭주는 금지.
- 동시에 터지는 소리를 개별 최대 볼륨으로 합산해 찢어지는(distortion) 소리가 나지 않게 limiter/compressor 또는 gain budget 사용.
- 아주 높은 콤보에서 매 타격마다 새 종소리·음성이 나오면 피로하다. 축하 스팅거는 주요 콤보 임계값당 1회.
- 사운드 재생 타이밍은 **시각 이벤트 발생과 같은 틱**. `setTimeout(150)` 같은 임의 지연 금지.
- 오디오는 사용자 제스처 이후 활성화. 음소거 및 볼륨 설정을 유지.
- 전체 오디오 끄기, 사운드 효과 끄기, BGM 끄기 옵션 제공(이미 존재하는 UI를 보존).
- 사용자 터치 후 로드된 사운드가 없어도 Canvas 효과만으로 게임은 정상 진행.

## 9.2 음악 템포(선택이지만 강하게 권장)

- 원본 음악 파일의 실시간 time-stretch까지 할 필요는 없음.
- 초반: 드럼이 드문 경쾌한 전자 아케이드 루프 → 중반: 하이햇 레이어 추가 → 후반: 짧고 강한 퍼커션 레이어.
- 배경음은 외부 스트리밍이 아닌 로컬 에셋/로컬 합성 사용.
- 음표의 박자에 게임 판정을 맞추지 말 것. **플레이어 입력이 최우선**.

# 10. 필살기: 건물 전체가 산산조각 나는 최대 보상

기존의 `X` / 필살기 게이지 100 / 현재 건물 전체 제거 로직은 유지하되, 체감 품질을 다음으로 끌어올린다.

```txt
T +   0ms  : X 입력 처리, 게이지 0, 해당 건물 전체 파괴 논리 확정, 무적
T +  40ms  : 화면 명도 1차 펄스, 캐릭터 공격 자세가 크게 확장
T + 100ms  : 점프/상승 잔상과 대형 검광이 건물을 관통
T + 150ms  : 건물의 남은 모든 층에 순차적인 절단선 출현 (논리 판정 없음)
T + 230ms  : 위부터 아래/아래부터 위 중 한 방향으로 다층 폭발 연출
T + 350ms  : 큰 조각·작은 파편·재질별 입자 떨어짐, 점수 상승
T + 550ms  : 화면 정상 복귀, 다음 건물 전환 준비
T + 650ms  : 다음 건물 진입 (환경·성능에 따라 최대 0.8s)
```

- 화면에 남는 시각적 건물 잔해는 타격 판정·점수 지급이 다시 일어나지 않는 **render-only ghost**다.
- 필살기 발동 첫 틱에 건물 `defeated=true`, 라이프 보호 상태 확정. 중간의 건물이 바닥에 닿아 피격되는 버그 금지.
- 정적 xAI 컷인 이미지가 없다면 로컬 Canvas 검광/그라디언트/파편만으로 반드시 동작. 실행 중 xAI API 호출 금지.
- 모바일에서도 최장 0.8초 내 종료. 모든 건물에서 필살기 폭발 연출이 똑같은 평면 페이드가 되지 않게 재질별 파편 유지.

# 11. 렌더/물리/애니메이션 시스템 구조 (구현자 필독)

## 11.1 논리 → 이벤트 → 이펙트를 한 방향으로 연결

```txt
Input State / Input Buffer
      ↓
Fixed-step game rules (1/60s)
      ├─ Player physics (jump / movement)
      ├─ Building fall / segment HP
      ├─ Contact resolver (guard / attack / hazard)
      ├─ Score / combo / special
      └─ DOMAIN EVENTS
            ATTACK_SWING, ATTACK_HIT, FLOOR_CRACKED,
            FLOOR_DESTROYED, BUILDING_DESTROYED,
            JUMP_START, LAND, GUARD_CONTACT,
            GUARD_REPEL_START, GUARD_RELEASE,
            PLAYER_DAMAGED, SPECIAL_TRIGGERED
                    ↓
             GameFeel Effect Director
                 ├─ Animation pose
                 ├─ Camera impulses
                 ├─ Particle pool
                 ├─ Trail / flash
                 ├─ Score popup
                 └─ Audio mixer
                    ↓
            Canvas rendering (interpolated)
```

**필수:** 파티클이 HP를 직접 변경하거나 카메라 흔들림이 건물 충돌 좌표에 영향을 주는 구조를 허용하지 않는다.

## 11.2 게임 시간과 효과 시간은 별도

```js
function frame(nowMs) {
  const realDt = clamp((nowMs - prevMs) / 1000, 0, 0.05);
  prevMs = nowMs;

  // 쉐이크 / 파티클 / 잔광은 hit-stop에서도 재생될 수 있다.
  effects.update(realDt);

  simulationAccumulator += realDt;
  while (simulationAccumulator >= FIXED_DT) {
    const input = inputQueue.consumeForTick();
    game.tick(FIXED_DT, input); // 게임 규칙은 동일 fixed dt로
    simulationAccumulator -= FIXED_DT;
  }

  renderer.render(game, effects, simulationAccumulator / FIXED_DT);
  rafId = requestAnimationFrame(frame);
}
```

위는 **구조 예시**이며 실제 hit-stop 적용 시 `game.tick()` 내부에서 `gameplayFrozenMs`가 남아 있으면 이동·낙하·콤보 소모를 일시 중지해야 한다. 렌더용 `effects.update()`는 독립 진행한다. **정확하게 25ms를 표현하려면 1/60초 고정 틱에서는 약 2틱**이므로 효과 표현을 실측·조정하고 코드에서 의도와 차이를 기록한다.

- `PAUSED`: gameplay 및 effect time 둘 다 중지(단 일시정지 UI는 예외).
- `HIT_STOP`: gameplay 물리는 잠시 중지, 충돌·중복 판정 정지, effect time은 진행.
- `GUARD_HOLD`: **전체 game pause 아님**. 건물 낙하 및 플레이어의 상대 접촉 물리를 해당 가드 페어에 대해서만 고정, 타이머는 지정된 guard-clock으로 진행.
- `SPECIAL_CUTIN`: 건물 파괴는 이미 완료, 컷인 효과 시간만 진행.
- 프레임이 밀려도 물리 substep 한도(예: 프레임당 4~5스텝)를 정해 브라우저가 영원히 따라잡느라 멈추지 않게 한다. 느린 프레임에서 게임이 기하급수적으로 빨라지거나 공격이 누락되어선 안 된다.

## 11.3 타격/가드/필살기 이벤트 중복 방지

```js
function emitOnce(type, entityId, sequenceNumber, payload) {
  const key = `${type}:${entityId}:${sequenceNumber}`;
  if (alreadyEmitted.has(key)) return false;
  alreadyEmitted.add(key);
  events.push({ type, payload });
  return true;
}
```

- `floorId`, `buildingId`, `attackId`, `guardContactId` 등 명확한 소유 키 사용.
- 처리된 이벤트 키는 건물/이펙트 생명주기에 맞춰 정리해 메모리 누수 방지.
- 리스타트와 화면 전환에서 `setInterval`, `keydown`, RAF 중복 등록 금지.
- `ATTACK_HIT` 한 번이 잘린 층을 2회 파괴하거나 점수를 2회 지급하면 심각한 실패.

## 11.4 화면 흔들림·줌은 논리 판정을 바꾸면 안 됨

- 논리 좌표(가드 plane/바닥/타격 레인)와 화면 렌더 좌표를 분리.
- Canvas 변환 순서는 `worldScale` → `cameraShake/zoom` → `entityRender`, 그리고 HUD는 별도 레이어.
- 약점/타격 히트박스는 화면 흔들림 이후의 픽셀 좌표가 아닌 **월드 좌표**.
- 가드 중 카메라 흔들림이 있어도 건물과 캐릭터의 접촉선이 찢어져 보이지 않게 동시 적용.

# 12. 모바일, 사운드 없는 플레이, 접근성, 성능

## 12.1 모바일 UX

- 가드 버튼 **누르는 순간** 캐릭터의 방어 자세가 보여야 한다. 접촉 전에는 건물에 영향 없음.
- 점프 버튼은 short tap/full hold 구분, 버튼 길게 눌러도 OS 선택 메뉴 등장 금지.
- 버튼 누른 상태에서 손가락이 버튼 밖으로 살짝 이동해도 입력 누락이 일어나지 않도록 pointer capture.
- 멀티터치에서 점프+공격, 가드+공격, 이동+공격을 지원하되 `GUARD_HOLD` 공격은 버퍼 우선.
- 브라우저 입력과 Canvas 터치 제스처가 충돌하지 않게 `touch-action: none`을 게임 조작 영역에 적용.
- 360×740 화면에서도 캐릭터가 **실제로 높게 뛰는 모습**, 접촉점, 낙하중 건물의 밑면이 모두 보이도록 카메라/스케일을 조정.

## 12.2 접근성·안전

- `prefers-reduced-motion` 또는 게임 `Effects: LOW`에서 화면 흔들림 0, 잔상 및 파티클 수 최소화. **충돌/가드/점프의 실제 메커니즘은 그대로**.
- 전체 화면 흰색 플래시 반복 금지. 플래시는 **작은 타격 접촉면 중심** 및 밝기 상한 설정.
- 색깔만으로 HP 구분하지 않는다. 금간 표면/입자/재질 텍스처 등으로 구분.
- 음소거에서도 타격 프레임/가드 접촉/완파가 명확히 읽혀야 한다.
- 오버레이가 조작 버튼·목숨·약점·최하층을 가리지 않게 한다.

## 12.3 성능 기본 목표

- 데스크톱 최신 브라우저: 60FPS 목표, 저사양/모바일 30FPS에서도 판정 일관성.
- 한 프레임 파편 수 상한: 데스크톱 260 / 모바일 140개. 더 필요하면 LOD/오브젝트 풀 활용.
- 잔해를 매 프레임 새 PNG/WebP로 변환하거나 CPU `getImageData()`로 화면 전체를 분석하지 않는다.
- 큰 건물 이미지 crop 조각은 **오프스크린 캔버스/미리 계산된 마스크** 캐시.
- 이펙트가 없어도 타격·가드·점수·목숨이 진행되는 **논리/렌더 독립 테스트** 필요.
- xAI/Grok API 호출: 브라우저 네트워크 검사 기준 **0건**.

# 14. 구현 파일 배치 제안 (기존 구조에 맞춰 병합)

기존 프로젝트가 `src/` 단위가 아니면 파일을 그대로 강제하지 말고 같은 역할의 모듈에 통합한다.

```text
src/
  game/
    config/
      gameFeel.js              # 점프/가드/타격 정지/이펙트 수치 단일 소스
    systems/
      PlayerJumpSystem.js      # 비대칭 중력, variable jump, landing
      GuardContactSystem.js    # 접촉 plane, swept 충돌, 접촉 상태기계
```

### 성능/거리 검증 방법

- 월드 좌표를 기록하는 테스트 모드를 만들고 `player.feetY`, `player.vy`, `building.bottomY`, `guardPlaneY`, `guardPhase`, `collisionGap`, `jumpApex`를 매 틱 샘플링한다.
- 가드 `GUARD_HOLD` 중 `abs(building.bottomY - guardPlaneY) <= 2wu`가 유지되어야 한다.

- `GUARD_RELEASE` 경계에서 한 틱 이동거리의 불연속이 보이지 않아야 한다.

## 15.2 반드시 수행할 육안 QA — 키를 눌러 직접 확인

### QA-A. '높이 뛰는 게 보이는가?'
1. 시작 후 건물이 내려오기 전 점프.
2. **캐릭터 키의 약 3~4배 높이**로 확실히 상승.
3. 점프를 빨리 놓으면 낮게 뜨고, 홀드하면 높게 뜸.
4. 공중에서 Z를 눌러 자연스럽게 공격하고 착지.
5. **불합격 예:** 발만 짧게 떼거나 건물 밑면에 닿지도 못하고 늘 같은 높이에서 툭 떨어짐.

### QA-B. '가드하면 딱 닿고 정말로 버티는가?'
1. 건물이 플레이어 머리 위로 가까워질 때 ↓을 누른다.
2. **손/무기와 건물 밑면 사이에 빈 공간이 없이** 접촉한다.
3. `쿵` 사운드와 함께 약 0.12초 **낙하가 멈춤**.
4. 잠깐의 압축 이후 **눈에 보이게 위로 밀어 올림**.
5. 밀어낸 후 다시 건물이 서서히 낙하를 시작.
6. **불합격 예:** 버튼을 누르는 순간 멀리서 건물이 위로 이동, 가드 후 85wu 텔레포트, 얼굴/칼이 건물 속으로 박힘, 닿지 않은 채 가드 성공.

### QA-C. '층을 없앴다는 시원함이 있는가?'
1. HP 1 약점을 찾아 Z 한 번.
2. 정확한 층에 검광이 닿음 → **전체 층이 터짐**.
3. 큰 조각·잔가루·먼지가 재질에 맞게 폭발하고 건물 상부가 미세 반동.
4. 박진감 있는 타격음, 즉시 점수 상승 및 콤보 반응.
5. **불합격 예:** 층 전체가 아무 감각 없이 opacity만 줄어듦, 한 레인만 비어 있음, 조각이 캐릭터 몸에서 터짐.

### QA-D. '연타할수록 리듬이 사는가?'
1. 건물 3~5채를 공격/점프/가드하며 연속 플레이.
2. 연속 공격이 캐릭터의 교차 검격/다른 타격음을 만들어 낸다.
3. 10/25/50 콤보의 기분 좋은 시각적 차이.
4. 위기 순간 가드/필살기 → 뚜렷한 역전 반응.
5. **불합격 예:** 시작부터 끝까지 똑같은 휘두름과 똑같은 플래시. 화면은 화려하나 게임은 지루함.

### QA-E. '빠르지만 공정한가?'
1. Tier 1/3/5/6에서 같은 테스트를 반복.
2. 어려워질수록 건물 낙하속도와 필요한 공격 횟수가 실제 증가.
3. 위험 경고가 충분히 읽히고 가드·공중 공격으로 대응 가능.
4. 셰이크·필살기 화면 가림 때문에 약점 판독 실패가 발생하지 않음.

### QA-F. '모바일에서도 같은 손맛인가?'
1. 360×740 세로 화면에서 점프+공격 멀티터치.
2. 긴 점프, 접촉 가드, 층 파괴가 화면 밖으로 잘리지 않고 판별 가능.
3. 소리 끔 + 저사양 이펙트 모드에서도 동일 판정.

# 16. 디버그용 개발자 도구 — 구현 속도를 높이려면 필수

개발 전용 `?debugFeel=1` 또는 개발 환경 키 조합에서만 제공. 일반 사용자에게 노출하지 않는다.

### 실시간 조절 가능한 슬라이더/토글

- 점프 초기속도 `-650 ~ -1000wu/s`
- 상승 중력 `1300 ~ 2200wu/s²`, 하강 중력 `1900 ~ 3400wu/s²`
- 가드 접촉 거리 `8 ~ 22wu`
- 가드 버팀 `80 ~ 180ms`
- 지상 반발거리 `55 ~ 110wu`, 공중 `20 ~ 55wu`
- 지상/공중 반발시간 `120 ~ 300ms`
- 공격 주기 `80 ~ 120ms`
- 타격 정지 시간 `0 ~ 85ms`
- 파편 개수/시간/중력, 카메라 흔들림 배율 `0 ~ 1.3`
- 카메라 hitbox / 가드 접촉선 / activeFloor 색상 표시 (개발 모드)
- 사운드 on/off·시각 효과 on/off·강도 프리셋.

### 단축 재현 버튼

- `Jump Test`: 빈 건물 공간에서 캐릭터가 최대 점프로 1번 시연.
- `Guard Ground Test`: 지상 가드 직전 거리로 건물 1개 생성.
- `Guard Air Test`: 공중 가드 접촉 높이로 건물 1개 생성.
- `One-Hit Floor Test`: 현재 최하층 `[1,2,3]` 설정.
- `Destruction Test`: 층 재질을 유리·석재·철골·기와로 바꿔 파괴 연출 1번씩 실행.
- `Special Test`: 게이지 100으로 설정.
- `High Difficulty Test`: v1 Tier 5/6 데이터로 건물 생성.

**디버그 모드의 필수 로그:** 각 이벤트의 `timestamp, buildingId, floorId, contactGap, jumpApex, guardPhase, bottomY, collisionKind, emittedOnceKey`를 볼 수 있게 한다. 게임 사용 중 콘솔 로그 스팸 금지.

# 18. 마지막 완료 판정 (이 기준 미달 시 '완료'라고 보고 금지)

## 플레이 감각 필수 10개

1. **점프:** 이전보다 2배 이상 높으며, 풀 점프가 약 200wu라서 멀리서도 높이 솟는 게 분명함.
2. **점프 리듬:** 길게/짧게 누르면 차이가 있고, 가파르게 내려와 착지가 명확하며 공중 공격 가능.
3. **가드 접촉:** 캐릭터의 손/무기와 건물 밑면이 **딱 맞닿음**. 떠 있는 방어 이펙트만으로 처리하지 않음.
4. **가드 버팀:** 접촉 직후 약 0.12초 건물이 **그 자리에 멈춤**. 그동안 캐릭터가 압축되며 버팀.
5. **가드 반발:** 버틴 다음 지상 85wu / 공중 35wu **연속적으로 밀어 올림**. 순간이동 금지.
6. **강한 공격감:** 한 타마다 캐릭터 동작·검광·타격점·재질 반응·사운드가 동기화.
7. **층 파괴:** 약점 HP0에서 **그 층 전체가 0~90ms 안에 터지며**, 큰/작은 파편, 먼지가 실제 층에서 비산.
8. **템포:** 연타가 부드럽고 카메라 흔들림·hit-stop이 짧고 정확하며 **입력 지연이 없음**.
9. **몰입:** 콤보, 위험 근접, 가드 역전, 필살기, 건물 완파에서 **서로 다른 강도의 분명한 보상**이 있음.
10. **무결성:** 기존 3레인/HP/목숨/점수/콤보/필살기/난이도/랜드마크 기능 유지, 중복 파괴·가짜 이펙트·런타임 AI 호출 없음.
