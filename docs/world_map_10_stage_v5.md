# WORLD BREAKER — 월드맵 & 10단계 스테이지 진행 시스템 v5.0

> **Claude Code / Cursor용 추가 구현 명세**  
> 기존 건물 부수기 게임에 **레벨 1~10 로드맵, 순차 해금, 낮→밤의 환경 변화, 레벨별 확실한 낙하속도 상승, 점진적 건물 난이도, 클리어/재도전/진행 저장**을 추가한다.
>
> **중요: 새 게임을 만들지 말고 현재 구현 위에 추가한다.** 기존 v1~v4의 공격·가드·목숨·필살기 수정은 유지. 본 v5는 **스테이지/맵/난이도 결정권만 갱신**한다. 기존의 엔드리스 모드를 삭제하지 않는다.

## 0. 이번 작업의 핵심 목표

게임 시작 시 랜덤한 건물이 곧바로 떨어지는 대신, 플레이어가 **하나의 긴 여정을 시작하는 월드맵**을 본다.

- **총 10개 레벨**이 하나의 구불구불한 길로 연결되어 있다.
- 첫 실행 시 **LEVEL 1만 플레이 가능**. 클리어할 때마다 다음 노드 해금.
- **레벨 1은 따뜻한 햇빛 아래 단순한 저층 건물 위주**로 진행하며, 조작을 배우되 지루할 만큼 느리지는 않다.
- **레벨 2부터는 시작부터 이전 레벨보다 뚜렷하게 빠르다.** 단순히 해당 레벨의 마지막 건물만 빠르게 만들지 않는다.
- 레벨을 올라갈수록 **한낮 → 오후 → 노을 → 땅거미 → 밤 → 깊은 밤**으로 어두워진다.
- 높은 레벨에서는 랜드마크와 복합 구조물이 등장하며, 속도·층수·약점 패턴이 함께 어려워진다.
- 난이도는 상승하되 **운 나쁜 랜덤 패턴으로 사실상 불가능한 상황이 나오면 안 된다**. 가드·공격·점프·스페셜로 돌파할 수 있어야 한다.
- 플레이 실패 시 레벨을 재도전한다. 이미 깬 레벨/메달/기록은 보존한다.

### 최종 사용자의 경험

```text
실행
  ↓
월드맵 (1 → 2 → 3 → ... → 10, 잠긴 노드 표시)
  ↓ Level 1 선택
따뜻한 밝은 낮 / 작은 빌딩 / 빠르지만 충분히 반응 가능한 낙하
  ↓ 3개 건물 파괴
STAGE CLEAR!  ★★★  → 다음 레벨 잠금 해제
  ↓ 지도에서 Level 2 선택
낮이지만 더 진해진 그림자 / 좀 더 높은 건물 / 시작부터 체감되는 가속
  ↓ ...
Level 5: 석양 / 복합 구조 / 가드와 레인 전환이 중요
  ↓ ...
Level 8: 야경 / 랜드마크 / 긴장감 높은 속도
  ↓
Level 10: 깊은 밤 / 대형 랜드마크 최종 연전 / 도전 가능하지만 높은 숙련 요구
  ↓
ALL CLEAR! / 결과 화면 / 완료한 월드맵 / 재도전 또는 엔드리스
```

**품질 목표:** 플레이어가 레벨을 한 번 클리어할 때마다 **“다음은 얼마나 빨라질까?”와 “배경이 어디까지 어두워질까?”**를 기대하게 만들 것.

# 2. 월드맵 화면 — 게임 시작의 첫 경험

## 2.1 구조

게임을 열면 풀스크린 **WORLD MAP**이 기본 화면이다. 처음 플레이할 때 자동으로 레벨 1의 노드에 포커스한다.

```text
┌──────────────────────────────────────────────────┐
│  WORLD BREAKER                  ★ 12 / 30         │
│  A JOURNEY FROM DAY TO NIGHT                     │
│                                                  │
│      [10] 🔒 ───── [9] 🔒     ← 가장 어두운 밤     │
│        ╲             ╱                           │
│         [8] 🔒 ─── [7] 🔒                         │
│          ╲         ╱                             │
│          [6] 🔒─[5] 🔒       ← 석양·해 질 녘      │
│             ╲      ╱                             │
│             [4] 🔒─[3] 🔒                         │
│                    ╲                             │
│          [1] ▶ ─── [2] 🔒     ← 밝은 낮           │
│                                                  │
│       ┌──────────────────────────────┐           │
│       │ LEVEL 1 · 햇살 아래 첫 타격  │           │
│       │ 난이도: 쉬움  | 낮 | 3채     │           │
│       │     [ 도전하기 ]            │           │
│       └──────────────────────────────┘           │
│                                                  │
│  [엔드리스] [설정]   진행 상황 자동 저장         │
└──────────────────────────────────────────────────┘
```

**위 그림은 구조 설명용 ASCII 와이어프레임이지 최종 그래픽 배치가 아니다.** 실제로는 S자형/지그재그 길에 10개 노드가 자연스럽게 배치되어, 밝은 지역에서 어두운 지역으로 탐험하는 구도다.

### 지도 상의 시각 요소

- 노드 10개를 항상 인지할 수 있어야 한다. 모바일에서는 **스크롤 가능한 세로 지도**, 현재 진행 중인 노드로 자동 스크롤.
- 길은 커브를 가진 점선/돌길/에너지 라인 등으로 연결하되, **연결 순서가 1→2→...→10임을 확실히** 표현.
- 클리어한 노드는 환하게 빛나고 별 개수 또는 체크 표시.
- 다음 도전 가능 노드는 가장 강한 강조 표시 + 짧은 호흡 애니메이션.
- 아직 잠긴 노드는 반투명·자물쇠로 표시. 클릭하면 ‘이전 레벨을 클리어하면 열립니다’ 안내, **진입 불가**.
- 레벨을 탭하면 **이름, 시간대, 대표 건물 실루엣, 목표(건물 수), 최고 기록, 도전 버튼**이 노드 옆/아래 패널에 뜬다.
- 지도에서 **레벨 1은 하늘이 맑고 밝으며, 레벨 10 쪽으로 갈수록 전체 풍경이 밤으로 변하는 단일 파노라마**가 가장 좋다. 지도 배경 자체에서 시간의 흐름을 읽을 수 있게.
- 맵의 길과 노드는 실제 클릭 영역이 명확해야 한다. 배경 그림에 버튼처럼 보이는 장식만 넣지 말 것.

## 2.2 입력 / 모바일 규칙

- PC: 클릭 + 방향키로 노드 포커스 이동, Enter로 정보 열기/도전. Esc로 선택 패널 닫기.
- 모바일: 노드 탭, 손가락 세로 스크롤, 하단 안전영역을 침범하지 않는 고정 도전 버튼.
- 현재 노드가 잠겨 있다면 시각적으로 잠금 상태를 안내하고 플레이 진입은 차단.
- 지도 로드가 끝나면 마지막 도전 가능 노드 근처를 보여주되, 사용자가 직접 1~10 전체를 탐색할 수 있어야 한다.
- 월드맵은 게임 내부 화면 전환이다. 페이지 전체 리로드로 진행 상태를 날리지 않는다.
- **처음 시작에는 설명 팝업을 여러 개 연속으로 띄우지 않는다.** 레벨 1 도전 버튼 근처에 간단한 한 줄 설명만.

## 2.3 레벨 클리어 후 지도 반응

1. 결과 화면에 `LEVEL N CLEAR!`, 획득 별, 점수, 사용한 목숨, 최대 콤보 출력.
2. `다음 레벨로` → 지도에서 `N+1`로 이동하고, 연결된 길이 서서히 밝아지며 잠금 해제 연출(약 0.6~1.0초).
3. `다시 도전` → 해당 레벨의 초기 상태로 즉시 재시작.
4. `월드맵` → 지도 복귀. 별/해금 정보 보존.
5. Level 10 클리어 → `WORLD COMPLETE` 특별 화면. 지도 모든 노드 점등, 자유 재도전/엔드리스 제공.

# 3. 10레벨 월드 전체 콘셉트 / 정확한 난이도 표

**다음 표의 속도는 `world units per second` 절대값이다. v4의 누적 파괴 수 티어 속도와 혼합 금지.**

| Lv | 테마 / 하늘 | 첫 건물 속도 (wu/s) | 레벨 마지막 웨이브 속도 | 건물 수 | 논리 층수 범위 | 약점 레인 출현 최소 비율* | 난이도 핵심 |
|---:|---|---:|---:|---:|---|---:|---|
| 1 | 맑은 오전 · 햇살 | **190** | 198 | 3 | 3~4 | 100% | 가드/점프/공격 학습, 작은 건물 |
| 2 | 밝은 오후 · 그림자 | **225** | 234 | 3 | 3~5 | 100% | 시작부터 Lv1보다 빠름 |
| 3 | 따뜻한 오후 | **260** | 270 | 4 | 4~6 | 95% | 처음으로 빠른 레인 선택 |
| 4 | 황금빛 늦은 오후 | **305** | 317 | 4 | 5~7 | 90% | 건물 높이 상승, 약점 이동 |
| 5 | 붉은 노을 | **355** | 369 | 4 | 6~8 | 85% | 복잡한 구조, 석양 보스급 랜드마크 |
| 6 | 보랏빛 땅거미 | **405** | 421 | 5 | 6~9 | 80% | 가드를 써야 안정적으로 버팀 |
| 7 | 도시의 저녁 불빛 | **455** | 473 | 5 | 7~10 | 70% | 2타·3타 부위 많아짐 |
| 8 | 깊어지는 야경 | **505** | 525 | 5 | 8~11 | 65% | 높은 탑, 연속 접촉 대응 |
| 9 | 어두운 한밤 | **560** | 582 | 5 | 9~12 | 60% | 짧은 TTC, 가드→반격 연계 |
| 10 | 깊은 밤 · 달빛과 전광 | **620** | **645** | 6 | 9~14 | 55% | 최종 러시. 어려워도 정당하게 깰 수 있음 |

\* `약점 레인 출현 최소 비율` = 한 **논리 층**의 3개 공격 구역 중 `HP=1`인 레인이 **적어도 하나** 존재하는 층의 비율을 보장하는 생성 조건. 가령 Lv10의 55%는 14층짜리 건물에서 최소 `ceil(14×0.55)=8`개 층에 최소 HP1 레인을 제공한다는 뜻이다. 나머지 층도 `HP2` 또는 `HP3`으로 반드시 파괴 가능해야 한다.

**표는 최초 권장 밸런스이며, 실제 브라우저 플레이 테스트에서 TTC와 클리어율을 확인한 뒤 한곳의 설정 데이터로 조정한다. 임의의 고정된 '원작 공식값'으로 취급하지 않는다.**

### 레벨 사이 체감 차이에 대한 강제 조건

- 레벨 1의 마지막 건물 속도 198 → 레벨 2 첫 건물 225. **시작하자마자 약 14% 빠름**.
- 레벨 2 마지막 234 → 레벨 3 시작 260. **레벨 사이 속도 역전 금지**.
- 모든 레벨에서 `startSpeed(nextLevel) > finalSpeed(previousLevel)`을 만족해야 한다.
- 레벨 9 마지막 582 → 레벨 10 첫 건물 620. 마지막 진입 시에도 **속도가 확실히 증가**.
- 레벨 10의 상한은 v4 물리 기준 **650wu/s**를 넘지 않는다.
- 레벨 1도 너무 느리게 하지 않는다: 190wu/s부터 시작. 1레벨이라고 100~115wu/s로 다시 낮추지 말 것.

### 같은 레벨 내부에서도 서서히 가속

각 레벨의 웨이브 진행 `0..(waveCount-1)`을 기준으로:

```js
function resolveStageFallSpeed(levelConfig, waveIndex) {
  const lastIndex = Math.max(1, levelConfig.waveCount - 1);
  const t = Math.min(1, Math.max(0, waveIndex / lastIndex));
  const speed = levelConfig.baseFallSpeed * (1 + 0.04 * t);
  return Math.min(650, Math.round(speed));
}
```

**중요:** 한 건물이 떨어지고 있는 도중에 속도가 갑자기 변경되어 튀지 않는다. **건물 생성 시 이번 웨이브의 목표 속도를 결정**하고, 가드/공격 반발을 제외하면 그 목표값을 유지한다. 다음 건물로 넘어갈 때 조금 더 빨라지는 구조.

# 4. 레벨별 건물 구성 및 세계관 변화

원래 요구했던 **경복궁·롯데월드타워·부르즈 할리파 등 랜드마크**를 유지하되, 초반에는 너무 복잡한 기념물보다 단순하고 작은 구조물부터 시작한다.

> `basic_*`는 새로 추가하는 **게임 전용 가상 건물**(단층 가게/저층 빌딩/아파트 등). 실존 건물은 기존 12개 목록과 메타데이터를 재사용. 새 에셋은 **개발 중** 생성·저장한 다음 정적으로 포함.

| Lv | 주 건물 예시 (웨이브별 풀) | 시각적 테마 | 추가되는 플레이 도전 |
|---:|---|---|---|
| 1 | 작은 상가, 3층 주택, 낮은 사무실 | 밝은 파스텔 거리 | 한 층의 약점을 찾는 기본 조작 |
| 2 | 오래된 상가, 중소형 오피스, 저층 아파트 | 화창한 도심 | 떨어지는 속도 차이 학습 |
| 3 | 저층 오피스, 시계탑, 피사의 사탑(단순화) | 고층이 보이기 시작하는 시가지 | 약점이 좌우로 바뀜 |
| 4 | 경복궁, 콜로세움, 도심 빌딩 | 황금빛 도시 / 역사 건축 | 지붕·아치 같은 비정형 파괴 구간 |
| 5 | 도쿄 타워, 에펠탑, 중형 랜드마크 | 석양, 길어진 그림자 | 철골 구간, 끝 웨이브 하이라이트 |
| 6 | 빅벤, 엠파이어 스테이트 빌딩, 타이베이 101 | 하늘이 보랏빛으로 전환 | 연속 2타 구간 증가 |
| 7 | 타이베이 101, 시드니 오페라 하우스, 대형 사무 빌딩 | 도시 불빛 켜짐 | 약점 없는 층 일부 등장 |
| 8 | 롯데월드타워, 페트로나스 트윈 타워, 에펠탑 야간판 | 짙은 파란 야경 | 긴 구조, 빠른 접근과 가드 연계 |
| 9 | 페트로나스, 롯데월드타워, 엠파이어 스테이트 야간판 | 심야 네온과 구름 | 짧은 반응 시간, 엘리트 변형 |
| 10 | 초고층 랜드마크 총집합, **부르즈 할리파 최종 웨이브** | 깊은 남색 밤, 달빛, 도시 전광 | 최종 연전, 빠른 가드/스페셜 사용 |

### 중요한 구현 규칙

- `실제 건축물의 실물 층수 ≠ 논리 층수`. 부르즈 할리파가 163개 논리 층이어야 하는 것은 아니다. Lv10 최종 건물도 최대 14개 공격 세그먼트로 밸런싱.
- 같은 랜드마크의 외형을 레벨에 따라 재사용 가능. **해당 레벨의 논리 층수, HP, 속도는 stage data가 결정**한다.
- 기본 건물이 없을 경우 임시로 단순 도형을 사용해 스테이지 동작을 먼저 검증하지만, 최종 결과물에서는 **캐릭터·건물의 선명한 정적 아트 에셋**으로 교체해야 한다.
- 배경은 건물보다 시각적으로 복잡해서는 안 된다. 게임 핵심 실루엣과 공격 접촉면을 명확히 볼 수 있어야 한다.
- **레벨 1~3에 복잡한 최상급 랜드마크를 랜덤으로 뽑지 말 것**. 레벨 테마와 난이도를 침범한다.
- Lv5 마지막과 Lv10 마지막은 특별히 인상적인 랜드마크/마지막 건물 등장 연출을 넣어도 되나, 공격 판정 자체는 동일하다.
- 같은 레벨 안에서 같은 건물이 연속으로 두 번 등장하는 것은 가능한 한 피한다(풀 크기가 허용할 때).
- 각 웨이브의 구성은 seed 기반으로 재현 가능해야 하며, `level10 wave6`은 반드시 부르즈 할리파로 고정.

# 5. 스테이지 개별 진행 규칙

## 5.1 웨이브 수와 클리어 조건

- 표에 지정된 **건물 수 = 웨이브 수**. Lv1은 3개, Lv10은 6개.
- 한 웨이브에서 하나의 건물만 낙하한다. 2개 건물 동시 낙하 금지.
- 건물을 완전히 파괴하거나 스페셜로 전체 파괴하면 `waveCleared += 1`.
- **목표 수의 건물을 모두 파괴하면 STAGE CLEAR**. 마지막 건물에 대한 스페셜 연출/파편 연출이 끝난 후 결과창 전환.
- 건물에 깔려 파괴하지 못한 경우(v4 피격 처리) **웨이브는 실패로 끝난 것이며 클리어 카운트에 포함하지 않는다**. 새 건물은 **같은 웨이브 번호에서 새 인스턴스**로 출현. 진행 목표를 몰래 줄이거나 다음 웨이브로 넘기지 말 것.
- 목숨은 **각 레벨 시작 시 3개**. 레벨 내부 웨이브 사이에는 보충하지 않는다. 다음 레벨 진입 시 3개로 새 시작.
- 실패 시 그 레벨을 처음부터 재도전. 잠금이 이미 해제된 다른 레벨은 별도 선택 가능.
- **가드는 무제한**이며 레벨에 관계없이 동일하게 작동한다. 스페셜은 각 레벨 시작 때 0에서 충전(진행 재시작 시도 마찬가지).

## 5.2 게임 상태 흐름

```text
MAP
 └─ SELECT_LEVEL(해금 검증)
     └─ STAGE_INTRO(0.7~1.1초, 배경/제목만 빠르게 표시)
         └─ PLAYING
             ├─ FLOOR_BREAK / GUARD / JUMP / ATTACK
             ├─ BUILDING_CLEARED
             │   ├─ 다음 웨이브 → SPAWN_NEXT → PLAYING
             │   └─ 마지막 웨이브 → STAGE_CLEAR
             ├─ CRUSH_DAMAGE(기존 v4)
             │   ├─ lives>0 → 같은 웨이브 안전 재시작
             │   └─ lives=0 → STAGE_FAILED
             └─ PAUSE → RESUME / RETRY / WORLD_MAP
STAGE_CLEAR
 ├─ SAVE_PROGRESS(정확히 한 번)
 ├─ RESULT_SCREEN
 └─ WORLD_MAP / NEXT_LEVEL / RETRY
STAGE_FAILED
 └─ RETRY / WORLD_MAP
```

### 전환의 체감 속도

| 연출 | 목표 시간 |
|---|---:|
| 레벨 입장 타이틀 | 0.7~1.1초, 언제든 스킵 가능 |
| 일반 건물 사이 전환 | 0.25~0.40초 |
| 레벨 마지막 건물 파괴 → 결과 | 파편·스페셜 완료 후 약 0.4~0.7초 |
| 다음 레벨 해금 연출 | 0.6~1.0초 |
| 지도 진입/복귀 | UI 준비된 뒤 0.4초 이내로 반응 |

**긴 로딩화면과 불필요한 컷신으로 아케이드 속도감을 죽이지 말 것.**

## 5.3 각 레벨의 웨이브 마지막 연출

- Lv3/5/8/10 최종 웨이브에만 0.3초 내외의 짧은 `FINAL BUILDING` 인트로 가능.
- 이 연출 때문에 충돌 시간(TTC)이 몰래 줄어들어서는 안 된다. 실제 게임이 시작되기 전에는 물리 시계를 멈춘다.
- 마지막 건물 파괴는 파편·충격파·카메라·사운드가 평소보다 조금 강하다. 전체 화면을 가리는 지속적 섬광은 금지.

# 6. 점진적 난이도 상승 — '어렵지만 깰 만하게'의 정량 기준

## 6.1 난이도를 결정하는 네 변수

1. **절대 낙하속도**: 190→620~645wu/s. 가장 직접적인 긴장감.
2. **건물의 논리 층수**: 레벨 상승에 따라 증가. 건물 높이 자체가 체감 과제.
3. **각 층 3레인의 HP 패턴**: HP1 약점의 보장 비율을 점진적으로 축소, HP2/HP3 증가.
4. **약점의 레인 변화 빈도**: 단순히 공격을 누르는 것에서, 약점을 보고 이동하는 게임으로 전환.

난이도를 올리기 위해 **조작 반응속도·공격 입력 딜레이·가드 성공 확률을 나쁘게 조정하지 않는다.** 플레이어의 도구는 끝까지 믿을 수 있어야 한다.

## 6.2 HP 패턴 가이드

| 레벨 범위 | 레인별 HP 가중치 초기값 (1 / 2 / 3) | 패턴 특징 |
|---|---|---|
| 1~2 | 75% / 23% / 2% | 모든 층에 한 번에 깨지는 약점 존재 |
| 3~4 | 60% / 33% / 7% | 일부 레인 이동 요구 |
| 5~6 | 45% / 42% / 13% | 약점 없는 층 소수, 가드 활용 |
| 7~8 | 32% / 48% / 20% | 2~3타 부위 분명히 증가 |
| 9~10 | 25% / 45% / 30% | 단단한 구간 다수, HP1 보장은 별도로 적용 |

**생성 순서**: 세 레인의 HP를 먼저 뽑고 → 스테이지의 약점 보장층 수를 정확히 충족하도록 일부 층을 보정 → 이동·반응 측면에서 풀 수 있는지 검증 → 불공정하면 재생성.

### 절대 금지 패턴

- Lv1~2에서 HP1 레인이 없는 층.
- Lv1~4에서 연속 3층 이상 약점 레인이 한쪽 끝↔반대쪽 끝으로 번갈아 등장하는 과도한 이동 패턴.
- 어떤 레벨에서도 **HP3/HP3/HP3인 층이 연속 2번 이상** 등장하지 않도록 제한.
- 필살기가 없으면 무조건 피격되도록 강제하는 기믹.
- 첫 접촉까지 시간도 없이 스폰과 동시에 몸에 겹쳐서 나타나는 건물.
- 레벨 10이라는 이유만으로 가드가 무효가 되거나 공격이 원거리에서 통하도록 충돌 규칙 변경.
- 실존 건물 외형 때문에 터치 가능한 층의 레인 히트박스가 불규칙하게 실종되는 구조.

## 6.3 빠른 낙하에서 가드 사용을 유도하는 방법

- 레벨이 올라갈수록 낙하 자체가 빨라져 **가드로 순간 정지시키는 가치가 커진다**.
- Lv1부터 가드를 사용할 수 있지만 필수가 아니다. Lv4 이후 유리해지고, Lv7 이후에는 숙련 플레이어도 자주 쓰게 된다.
- 실제 캐릭터-건물의 가드 접촉일 때만 건물이 `고속 낙하 → 120ms 정지 → 살짝 튐 → 재낙하`.
- 가드를 누른 채 건물 도착을 기다리는 입력도 허용. 접촉을 조건으로 성공 판정. 가드 게이지/소모 자원 없음.
- 가드 사용 후 **영구 정지·위치 텔레포트·끝없는 무적 루프를 만들어서는 안 된다**. 매번 새 물리적 접촉 이벤트가 있어야 재가드 연출.
- 기존 v4의 swept collision 및 접촉 우선순위 유지. 30fps 이하나 빠른 속도에서도 경계 관통 금지.

## 6.4 TTC(접촉까지 남은 시간) — 체감 속도 검증

`speed` 숫자만 높아도 출현 위치가 지나치게 멀면 느리게 느껴진다. 아래는 **처음 등장한 건물의 하단이 캐릭터 가드 면에 도달하기까지** 목표 시간.

| 레벨 | 등장 → 첫 접촉 목표 TTC |
|---|---|
| 1 | 1.55~1.95초 |
| 2 | 1.35~1.70초 |
| 3 | 1.20~1.50초 |
| 4 | 1.05~1.35초 |
| 5 | 0.92~1.20초 |
| 6 | 0.82~1.10초 |
| 7 | 0.72~1.00초 |
| 8 | 0.65~0.90초 |
| 9 | 0.58~0.82초 |
| 10 | 0.55~0.76초 |

- 초기 생성 위치에서 `predictedTTC = max(0, playerContactY - buildingBottomY) / speed`가 목표 범위에 들어가도록 `spawnBottomY`를 계산한다. 실제 좌표계의 위/아래 방향 및 충돌 표면 기준을 반영한다.
- 화면 세로 공간이 부족하면 건물 **위쪽 부분은 화면 밖에서 시작해도 되지만**, 최초 시각적 하단이 플레이어와 겹친 상태로 스폰하지 말 것.
- `spawnY`를 데이터 테이블에 무작정 하드코딩하는 방식보다 **접촉표면 + TTC로 계산**하는 방식 권장.
- 건물의 층이 파괴되어 다음 최하층이 내려올 때는 v3/v4의 물리 경로로 자연스럽게 재접촉해야 한다.
- **반응 가능한 최소 시간**을 해치는 화면 배율/카메라의 변경은 출시 전 반드시 테스트한다.

## 6.5 플레이테스트 목표 (초기 휴리스틱, 확정 보장 아님)

- 처음 하는 플레이어의 Level 1~2 클리어율은 **70~90%**를 우선 목표로 관찰. 실패해도 왜 실패했는지 이해할 수 있어야 한다.
- Level 3~5: 처음 한두 번의 도전 끝에 익숙해지면서 성공하는 난이도.
- Level 6~8: 가드·점프·레인 이동을 익힌 사용자는 여러 번 시도하여 클리어 가능.
- Level 9~10: 고난도지만 숙련자 테스트에서 **재현 가능한 클리어 루트** 존재.
- 초기 수치는 **플레이 테스트 없이 절대적 난이도를 보장하지 못한다.** 자동화 시뮬레이션+실사용자 플레이 기록으로 조정한다.
- 막힌 레벨이 확인되면 **먼저 TTC·약점 배치·층수**를 수정하고, 원거리 공격 허용이나 가드 판정 확률 감소 같은 잘못된 방식으로 해결하지 않는다.

# 7. 낮→밤의 점진적 시각 변화 (이번 기능의 주인공)

## 7.1 레벨별 환경 데이터

배경 아트가 바뀌는 것뿐 아니라 **하늘 색, 태양/달, 구름/별, 도시 창문 불빛, 그림자, 파티클, 주변광, 음악 분위기**가 자연스럽게 이어진다.

| Lv | 시간대 | 하늘 팔레트 예시 | 광원/배경 디테일 | 정서 |
|---:|---|---|---|---|
| 1 | 오전 10시 | `#78CBFF → #DDF4FF` | 밝은 구름, 따뜻한 햇빛 | 시작, 가벼움 |
| 2 | 오후 1시 | `#58BFF6 → #CDEEFF` | 또렷한 그림자 | 활기 |
| 3 | 오후 3시 | `#57A8ED → #D4E6F8` | 건물 뒤쪽 금빛 | 움직임 증가 |
| 4 | 오후 5시 | `#74A4DA → #F5D3A3` | 길어진 그림자, 황금빛 | 상승하는 기대 |
| 5 | 오후 6시 | `#C676A7 → #FFBC82` | 붉은 노을, 얇은 구름 | 중간 피크 |
| 6 | 저녁 7시 | `#544E9E → #CE83A6` | 첫 별, 도시 불빛 켜짐 | 긴장 시작 |
| 7 | 저녁 8시 | `#233F82 → #765B9F` | 네온과 가로등 | 높은 긴장 |
| 8 | 밤 10시 | `#142A61 → #345A89` | 도시 야경, 별 | 빠른 액션 |
| 9 | 자정 | `#0C183D → #273767` | 희미한 구름, 달빛 | 극한 직전 |
| 10 | 새벽 1시 | `#080F2B → #203E68` | 달빛, 먼 전광, 고층 건물의 창빛 | 최종 결전 |

**색은 시안용.** 기존 캐릭터/공격 검광/필살기 색상과 충돌하지 않도록 화면에서 명도와 대비를 확인하고 조정한다.

## 7.2 연출 규칙

1. **레벨 간 변화는 명확하지만 급격한 단절 없이.** 레벨 4에서 5로 넘어가면 노을이 깊어지고, 6부터 별과 조명이 조금씩 나타난다.
2. **레벨 내부에서는 시간대가 크게 점프하지 않는다.** 각 건물을 깰 때마다 구름/빛 강도가 미세하게 이동하는 정도의 변화만. 주요 일몰 단계는 레벨 전환에 맞춰 일어난다.
3. 배경은 3~4개 레이어: 하늘 → 멀리 있는 구름/산 → 도시 실루엣 → 가까운 거리. 각각 다른 속도로 패럴랙스.
4. Lv6 이후 차례로 별·가로등·창문 불빛이 나타난다. Lv9~10에서도 **건물의 공격 가능 구역·캐릭터·HP 시각 표시가 읽혀야 한다.** 어둡다는 이유로 게임을 의도적으로 안 보이게 만들지 않는다.
5. 밤의 짙은 배경 위에는 칼 검광, 가드 임팩트, 파편이 더 아름답게 보이도록 제한된 bloom/glow. 모바일 저사양에서는 간소화.
6. Level 10에 번개/전광 같은 먼 배경 연출을 넣을 수 있지만 **공격 판정 장애물이 아니며** 광과민성 위험을 줄이도록 짧고 약하게 제한. 기본은 달빛과 도시 조명.
7. 햇빛/그림자 정보는 **렌더 전용**. 조명 연출 때문에 실제 히트박스가 바뀌면 안 된다.
8. 레벨 내 건물과 카메라 흔들림에도 월드맵/게임 HUD 텍스트는 흔들리지 않는 별도 UI 레이어를 사용.

## 7.3 월드맵 전체는 '시간의 길'

- 지도 상단/하단의 위치가 시간 순서를 보여주고, 레벨 경로 주변의 하늘이 단계별로 색을 바꾼다.
- 지도는 10장의 개별 배경을 단순히 나열하는 것보다 **연속 그라디언트 + 지역별 일러스트 요소**를 합성하여 거대한 한 장의 여정처럼 보이도록 한다.
- 진행도가 높아지면 도달한 경로의 조명, 달성한 노드의 별빛, 밤거리의 불빛이 깨어나는 연출.
- **어두운 구간의 아직 잠긴 노드는 잠겨 있어도 보이게** 만들어 다음 단계에 대한 기대감을 준다.

# 8. 레벨 인트로 / HUD / 결과 화면

## 8.1 레벨 시작 인트로

짧고 힘있게. 예시:

```text
LEVEL 05 / 10
붉은 노을의 철골 숲
목표: 건물 4개 완파

[READY] → [BREAK IT!]
```

- 0.7~1.1초 내에 끝나는 오버레이. 스킵 가능.
- 레벨 1에서는 `Z 공격 / ↑ 점프 / ↓ 가드 / X 필살기`를 시작 패널에서만 작은 2줄 안내로 표시. 이전 스크린샷처럼 중앙에 글자가 한 글자씩 세로 배열되는 일 금지.
- 키 안내는 시작 메뉴·일시정지 메뉴에서 재확인. 플레이 공간에 긴 텍스트를 계속 붙여놓지 않는다.

## 8.2 플레이 중 HUD

```text
┌─────────────────────────────────────────────────────┐
│ LEVEL 5/10   2 / 4 BUILDINGS   ♥ ♥ ♥   SCORE 012400│
│ COMBO ×12                                 SPECIAL ███│
│                                                     │
│                   [GAME]                            │
│                                                     │
│                         [CHARACTER]                 │
└─────────────────────────────────────────────────────┘
```

- 필수: `LEVEL 5/10`, `파괴한 건물 수 / 목표 건물 수`, 라이프(♥×3), 점수, 콤보, 스페셜 게이지.
- **GUARD 게이지 / 바 없음.** 가드는 무제한.
- 현재 레벨의 시간대와 배경은 그 자체로 식별될 정도로 뚜렷해야 한다. 텍스트로 시간대를 HUD에 계속 적을 필요는 없다.
- UI는 중앙의 캐릭터와 건물 하단 접촉면을 절대로 가리지 않는다.
- 상단 HUD의 크기/여백은 모바일 safe area 및 노치 고려.
- 게임 옵션에 `월드맵으로 돌아가기`가 있어도 게임 중 우발적 탭으로 종료되지 않도록 일시정지 메뉴에서만 제공.

## 8.3 결과 화면

**클리어:**

```text
LEVEL 05 CLEAR!
★ ★ ☆
Score: 24,800
Best Combo: ×23
Remaining Lives: ♥ ♥

[다음 레벨] [재도전] [월드맵]
```

**실패:**

```text
LEVEL 05 FAILED
4개 중 3개 완파
Best Combo: ×18

[재도전] [월드맵]
```

### 별 획득의 간단한 표준 (수치 악용 없는 방식)

- **별 1개:** 레벨 클리어 자체.
- **별 2개:** 목숨 1개 이상 남기고 클리어(실패 후 재시도 세션은 별개).
- **별 3개:** 라이프 3개 그대로 클리어 (노 데미지).
- 이미 받은 최고 별 개수는 이후 실패/낮은 성적으로 덮어쓰지 않는다.
- **다음 단계 해금은 별 1개만으로 가능**. 3별을 강요하지 않는다.
- 결과 카드에 레벨 첫 클리어에서 새로 해금된 노드를 안내한다.

# 9. 지속 저장 / 해금 로직

## 9.1 localStorage 사용

서버 계정이 없는 MVP는 `localStorage`만으로 진행도 유지. 엔드리스 최고 기록과 분리한다.

```js
const STORY_SAVE_KEY = 'world-breaker:story:v5';

const DEFAULT_STORY_SAVE = {
  schemaVersion: 5,
  unlockedLevel: 1,
  highestClearedLevel: 0,
  levels: {}, // "1": { cleared: true, bestStars: 3, bestScore: 24000, bestCombo: 27 }
  totalStars: 0
};
```

### 저장 원칙

- `unlockedLevel` 범위 항상 `1..10`.
- 특정 레벨 성공(`levelId=N`) 시 `highestClearedLevel = max(old,N)`.
- `unlockedLevel = min(10, max(oldUnlocked, N+1))`.
- `bestStars`, `bestScore`, `bestCombo` 모두 `max(old,new)`.
- 총 별은 모든 레벨 `bestStars`의 합계로 파생(중복 누적 금지). 최대 30개.
- 새로운 레벨의 잠금 해제는 **실제 `STAGE_CLEAR` 전이에서만 수행**. 스페셜/파편 콜백이 두 번 실행되더라도 중복 해금/점수 반영 금지.
- 클리어 직후 원자적으로 읽기→갱신→쓰기. 저장 실패 시 사용자에게 알리고 재시도 안내. 메모리 안에서만 저장된 것을 영구 저장 성공으로 표시하지 않는다.
- 변경된 저장 데이터는 저장되자마자 월드맵과 결과 화면 양쪽에 반영.
- reload / 재방문 / 브라우저 복구 후 이전 해금 상태 유지.
- **기존 v1~v4 엔드리스 기록을 삭제하거나 초기화하지 말 것.**
- 저장 데이터가 손상되었으면 예외 처리 후 기본값으로 복귀하되, 사용자에게 진행 저장을 읽지 못했다는 안내를 표시.
- 설정의 `진행 초기화`는 별도 확인창을 거쳐서만 수행. 기본 버튼으로 배치하지 않는다.

## 9.2 유효하지 않은 레벨 진입 차단

```js
function canEnterStoryLevel(level, progress) {
  return Number.isInteger(level)
    && level >= 1 && level <= 10
    && level <= progress.unlockedLevel;
}
```

- 맵 클릭, 키보드 조작, URL 해시/쿼리 조작 등 모든 경로에서 검증.
- 레벨 10 클리어 후 엔딩을 여러 번 볼 수 있어야 한다. 클리어한 스테이지를 다시 플레이해도 저장 데이터가 나빠지면 안 된다.

## 10.2 웨이브 생성과 재현성

```js
function createStoryWave(stage, waveIndex, runSeed) {
  // 1) 검증: stage.level 1..10, waveIndex [0,waveCount) 범위
  // 2) seeded PRNG(seed = hash(stage.level, waveIndex, runSeed))
  // 3) waveIndex === last + finalWaveLandmark 지정 시 이를 최우선
  // 4) 나머지는 landmarkPool에서 선택, 인접 반복 방지
  // 5) stage.floorsRange 내 논리층 수 결정
  // 6) 각 층 HP1/HP2/HP3 레인 3개 생성
  // 7) 최소 ceil(floors * weakFloorGuarantee)개 층에는 HP1 보장
  // 8) 불공정 패턴(연속 HP3 only, 과도한 왕복 이동) 검사 후 보정
  // 9) 건물 목표 낙하속도 = resolveStageFallSpeed(stage,waveIndex)
  // 10) stage.ttcTarget 중간값을 바탕으로 spawnBottomY 산출
  // 11) 완성된 객체를 기존 building loader / physics에 전달
}
```

**주의:** 현재 건물에 깔려 같은 웨이브를 재시작할 때 랜덤 seed가 바뀌어 더 어려운 건물이 우연히 나오지 않도록 **해당 레벨 시도의 웨이브 데이터는 한 번 생성하여 재사용**한다. 레벨 전체 재도전은 새로운 runSeed를 선택할 수 있으나, 수준 밖의 랜덤 패턴은 허용하지 않는다.

## 10.3 상태 및 물리 분리

- `story-controller`는 **다음 건물을 언제 만들지, 어떤 데이터를 쓸지**만 결정.
- `physics`는 가드/낙하/공격의 단일 충돌 판정 소유권 유지. `story-controller`가 건물 `positionY`를 따로 매 프레임 변경하지 않는다.
- `stage config`가 결정한 `targetFallSpeed`를 기존 물리 엔진으로 주입. `guard 120ms hold`·밀어냄·재낙하에서 같은 목표값으로 복귀.
- stage UI/지도 애니메이션이 브라우저 프레임을 밀어도 물리 고정 타임스텝과 swept collision이 정상 동작해야 한다.
- 클리어 이벤트는 `buildingId + waveIndex + stageAttemptId` 기준으로 딱 한 번 처리.

# 11. 정적 아트 에셋 / xAI 제작 규칙

**사용자의 기존 규칙을 그대로 따른다: xAI API는 게임을 만드는 동안 이미지 에셋 제작에만 사용. 플레이 실행 중에는 이미지 생성 API나 텍스트 API 호출 금지.**

### 개발 단계에 준비할 에셋

1. **월드맵 배경**: 밝은 지역부터 깊은 밤으로 이어지는 세로 파노라마. 인터랙티브 노드/길/잠금/별은 가능하면 HTML/CSS/SVG 벡터로 별도 렌더(정확한 클릭 가능).
2. **레벨 배경 10종** 또는 최소 5개의 주요 시간대 기반 배경+CSS/Canvas 색 보간. 오전→야경이 확실히 구분되도록.
3. **기초 건물 4~5종**: 가게, 주택, 오피스, 아파트, 시계탑 등. 최종 게임 화면에서 알아볼 수 있는 정면 실루엣.
4. **기존 랜드마크 재사용**: 이름·외형 메타데이터·파괴 세그먼트 자산을 그대로 활용. 필요 시 밝은/야간 조명 변형만 추가.
5. **파편/먼지/가드 충격파/검광**: 가능한 기존 v2/v4 효과 재사용. 레벨 5·10의 색상/빛 정도만 차별화.
6. **음악 및 효과음**: 기존 로컬 자산 우선, 필요하면 별도 정적 자산 생성. 스트리밍 API를 런타임 호출하지 않는다.

**렌더 분리 필수:** 배경 이미지는 이미지일 뿐, 월드맵의 클릭 노드/스테이지 진행선/건물 충돌 판정은 이미지 속 픽셀이 아닌 별도 실제 데이터/Canvas/DOM 오브젝트여야 한다.

### 성능과 가독성

- 배경 이미지는 적정 해상도·압축(`webp`/`avif` 가능)으로 준비. 느린 네트워크에서 레벨을 눌렀을 때 자동 장애가 발생하지 않도록 선로딩 및 fallback.
- 장식용 미세 먼지/별 파티클은 모바일에서 감축.
- 밤 배경은 반드시 캐릭터의 외곽선과 건물 약점 표시가 보이게 **최소 대비 유지**.
- `prefers-reduced-motion` 사용 시 화면 흔들림, 지도 줌, 섬광 등은 줄이되 게임 메커니즘은 유지.
- 지도에서 선택 노드와 진행선은 `aria-label`, 키보드 포커스, 충분한 탭 영역을 갖춘다.

# 12. 상세 QA / 자동 테스트

## 12.1 지도·해금

- [ ] 첫 실행 → 무조건 월드맵, Level 1만 플레이 가능, Level 2~10 잠금.
- [ ] 모바일 지도에서 1~10 모두 스크롤로 확인 가능, 노드 숫자/길이 가려지지 않음.
- [ ] 잠긴 Level 6을 탭하거나 URL/함수로 진입 시도해도 실제 플레이로 들어가지 못함.
- [ ] Level 1 성공 → Level 2만 새로 해금. 이후 2→3→...→10 순서 유지.
- [ ] 이미 열린 Level 1~N은 자유롭게 재도전 가능.
- [ ] 새로 해금한 노드에 진행선 점등 및 지도 위치 이동 연출 발생.
- [ ] Level 10 완파 → 월드 완료, 재도전 및 엔드리스 진입 정상.

## 12.2 클리어/재도전/저장

- [ ] Lv1 3채 완파 시 즉시(연출 종료 후) 클리어; 2채만 완파하면 클리어 아님.
- [ ] Lv10 6채 완파 시에만 월드 완료.
- [ ] 건물에 깔렸을 때 생명 -1, **파괴하지 않은 웨이브는 클리어 카운트 증가 없음**. 같은 웨이브 재시작.
- [ ] 한 충돌에서 목숨이 2개 이상 줄어들지 않으며, 캐릭터가 건물 밑에 끼이지 않음(v4 회귀).
- [ ] 목숨 0 → 해당 레벨 실패, 다른 레벨 해금 안 됨.
- [ ] 동일 클리어 이벤트가 중복 발생해도 다음 레벨이 2단계 해금되거나 별이 중복 누적되지 않음.
- [ ] 1별/2별/3별 획득 조건과 bestStars 최대값 유지.
- [ ] 완료 후 새로고침해도 unlockedLevel/최고 별/점수/콤보 그대로.
- [ ] 엔드리스 기록이 스토리 저장에 덮이지 않음.

## 12.3 난이도 단위 테스트

- [ ] 모든 레벨의 `waveCount`가 표와 일치하고 실제 생성된 건물 수도 일치.
- [ ] Level 1 첫 웨이브 190, 마지막 약 198wu/s.
- [ ] Level 2 첫 웨이브 225 > Level 1 마지막 198.
- [ ] `startSpeed(L+1) > endSpeed(L)`가 `L=1..9` 전부 참.
- [ ] 각 레벨 웨이브 속도가 단조증가, 최대 650 이하.
- [ ] **v4 엔드리스 누적 파괴 수 티어가 스토리 모드 속도에 섞이지 않음**.
- [ ] Lv1~2 모든 논리 층에 HP1 레인이 최소 한 개 있음.
- [ ] Lv10 14층 생성 시 HP1 약점이 있는 층 최소 8개.
- [ ] Lv1~4 과도한 약점 레인 좌↔우 반복 방지.
- [ ] 어떤 레벨에도 HP3/HP3/HP3 층이 2개 연속 나오지 않음.
- [ ] 해당 레벨의 구조물 랜덤 선택이 landmarkPool을 벗어나지 않음.
- [ ] Level 10 마지막 웨이브는 항상 부르즈 할리파.
- [ ] 등장 TTC가 레벨별 목표값 범위 내. 모바일 세로 해상도에서도 충돌 겹침 스폰 없음.

## 12.4 기존 전투 시스템 회귀 테스트 (강제)

- [ ] 빈 공간 원거리 공격은 어떤 스테이지에서도 건물 HP 감소 없음.
- [ ] 물리적으로 근접 접촉 중 공격하면 정확히 해당 층의 HP 감소.
- [ ] 레벨 10의 빠른 낙하에서도 **가드 입력·홀드 + 실제 접촉이면 무조건 가드 성공**.
- [ ] 가드는 자원/게이지/사용횟수 제한 없음.
- [ ] 가드 성공 시 짧은 정지→살짝 반발→다시 빠른 낙하를 재현. 건물의 비정상 순간이동 없음.
- [ ] 스페셜로 마지막 건물을 모두 파괴한 뒤 결과 화면 전환은 스페셜 최종 연출 완료 후 단 한 번.
- [ ] 목숨 3개, 높이 점프, HUD 겹침 수정 모두 유지.
- [ ] 월드맵·인트로 상태에서 게임 물리/낙하/공격이 뒤에서 계속 돌지 않음.

## 12.5 실제 사람 플레이 검증

- [ ] Level 1: 조작을 배우는 중에도 타격이 시원하며 공격할 건물까지 몇 초씩 멍하니 기다리지 않음.
- [ ] Level 2: 첫 건물부터 Level 1보다 빠른 것을 사용자가 바로 인지.
- [ ] Level 3~5: 스테이지 증가에 따라 하늘빛과 난이도가 둘 다 달라진 것을 알아봄.
- [ ] Level 6~8: 노을→밤 변화를 확실히 느끼고 가드할 때 빠른 충돌을 세우는 쾌감이 있음.
- [ ] Level 9~10: 빠르지만 훈련된 플레이어가 가드/레인 이동/필살기를 이용해 실제 클리어 가능.
- [ ] 모바일 및 데스크톱, 키보드 입력, 높은/낮은 FPS에서 게임 판정 동일.
- [ ] HUD가 캐릭터와 건물 접촉면을 가리지 않고 글이 세로로 찢어지지 않음.

## 설계상의 최우선 판단

**레벨이 올라갈수록 재미가 커져야지, 컨트롤이 망가져서 억울해져서는 안 된다.**  
체감 난이도는 `속도↑ + 층수↑ + 약점 선택 난이도↑ + 어두워지는 분위기`로 만들고, **공격의 정확성·가드의 확실함·필살기의 통쾌함은 전 레벨에서 동일하게 유지**할 것.
