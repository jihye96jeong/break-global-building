# WORLD BREAKER — 건물 부수기 오마주 웹게임
## Claude Code 전달용 전체 구현 명세서 (MVP + 확장 명세)

> 버전: 1.0 · 작성 기준일: 2026-10-15  
> 목적: 고전 게임 **《斬るビル》(키루비루, 국내 통칭 '건물 부수기')**의 속도감·3열 공격·층 단위 약점 파괴·가드·점프·콤보·필살기 구조를 현대적인 싱글 페이지 HTML 게임으로 구현한다.  
> **가장 중요한 제한:** xAI/Grok Imagine API는 **개발 중 건물·배경·캐릭터·기타 정적 시각 에셋을 제작할 때만 호출**한다. 이용자가 게임을 열거나 플레이할 때는 **어떠한 xAI/AI API도 호출하지 않는다.** 모든 충돌·파괴·속도·물리·입력·점수는 로컬 JavaScript로 처리한다.

## 0. 개발 에이전트에 내리는 실행 지시

1. 먼저 현재 프로젝트 구조를 확인한다. 기존 게임이 존재하면 작동하는 기능을 파악한 다음 본 문서에 맞게 수정한다. 프로젝트가 비어 있으면 새 프로젝트를 구성한다.
2. **설명·목업·플랜 작성에서 멈추지 말고 동작하는 게임을 구현**한다. 정적 HTML/CSS/JavaScript 기반 단일 페이지 SPA로 완성한다.
3. 원작의 **핵심적인 손맛·판정 방식**을 우선 구현한다. 유명 건물 이미지가 멋져도 조작 반응이 느리거나 층 전체가 파괴되지 않으면 실패다.
4. 이 문서에서 `[MUST]`는 출시 필수 기능, `[SHOULD]`는 품질 필수, `[LATER]`는 2차 확장이다. 먼저 모든 `[MUST]`의 수용 기준을 만족시킨다.
5. xAI 에셋 생성 스크립트를 실제로 구현한다. 사용 가능한 개발 환경의 `XAI_API_KEY`가 있다면 실제 호출하고 생성 결과를 로컬 파일로 저장한다. 키가 없으면 **키가 없음을 보고**하고 로컬 플레이스홀더로 게임이 실행되도록 한다. AI가 생성한 척 파일을 위조하지 않는다.
6. 구현 후 직접 빌드/테스트를 실행하고 실패 원인을 고쳐 완성한다. 사용하지 않는 버튼, 가짜 게이지, 애니메이션만 있는 가짜 파괴 효과를 남기지 않는다.
7. 원작의 이미지·음원·소스코드를 무단 추출하거나 그대로 복제하지 않는다. 메커니즘에서 영감을 얻되, 그래픽·사운드·브랜딩은 새로 제작한다.
8. 예상과 달리 기존 저장소의 중요한 사항이 충돌할 경우 기존 기능 보존보다 **이 명세의 필수 게임 루프 완성**을 우선하며 변경 사항을 기록한다.

### 0.1 완료 정의(Definition of Done)

새 이용자가 별도 회원가입이나 API 키 없이 URL을 열어 `게임 시작`을 누르고, 3개 열을 움직이며 건물을 공격하고, **하나의 약점 타격으로 해당 층 전체를 제거**하고, 점프·공중/지상 가드·필살기를 사용하고, 난이도 상승을 경험한 후 3번째 목숨 소진 시 결과 화면을 볼 수 있어야 한다. 배포된 페이지의 네트워크 탭에는 xAI API 호출이 **0건**이어야 한다.

### 1.1 플레이 감각: 타협 불가

- **시작 후 1초 이내** 움직이고 공격할 수 있다. 불필요한 스토리 컷신이 없다.
- 공격 입력 직후 해당 프레임에 타격 피드백이 시작된다. 공격은 연타/누르고 있기 모두 빠르게 반복된다.
- 약점(HP 1)을 고르면 **1타 → 해당 층 전체가 화면에서 사라짐**이 명확히 체감된다.
- 층이 제거되면 위쪽 잔여 건물은 공중에 남고, 현재 최하층이 바뀌며 낙하가 이어진다.
- 위기에서 지상 가드는 위험을 크게 밀어내지만 콤보를 잃고, 공중 가드는 적게 밀어내지만 콤보를 유지한다.
- 필살기는 **현재 낙하 중인 건물 한 채 전체 파괴**가 기본. 시각 효과만 발생하고 실제 판정이 그대로 남는 오류는 금지.
- 연속 파괴할수록 빠르게 어려워져야 하며, 처음 2~3채는 규칙을 익힐 여유를 준다.

## 2. 원작 고증과 새 게임의 규칙 분리

### 원작에서 검증된 주요 특징

- 하늘에서 빌딩/탑이 **한 채씩** 떨어지며, 최하층부터 베어 없앤다.
- 왼쪽·중앙·오른쪽 3개 위치에서 공격한다.
- 원작의 대표적인 조작: `←/→` 이동, `↑` 점프, `↓` 가드, `Z` 공격, `X` 필살기.
- 한 층의 부분별 내구도는 대표적으로 **1 / 2 / 3타**. 약한 부분 한 곳을 깎으면 층 전체가 사라진다.
- 지상 가드는 더 크게 밀어내지만 콤보를 끊고, 공중 가드는 밀어내는 양이 적지만 콤보를 유지한다.
- 진행에 따라 더 높은 건물과 더 빠른 낙하가 등장한다. 필살기는 공격 성공을 통해 충전한다.
- 원작에는 제2막의 불상·비석·번개·화산 암석·달 보스 등 별도 패턴과 엔드리스 요소가 있다.

**중요:** 원작의 모든 수학적 수치(초당 픽셀 속도, 가드 게이지 소비량, 실제 점수식)는 신뢰할 만한 공식 코드 자료로 확인된 것이 아니다. 아래 수치값은 **신규 HTML 게임을 위해 정의한 구현값**이다. 원작에 있던 정확한 값이라고 소개하지 말 것.

**참고:** 2004년 당시 소개 기사에는 `X`를 가드와 기술 조작에 모두 사용한다고 표현한 부분이 있다. 상세 게임 설명·국내 공략에서는 `↓=가드 / X=필살기`로 기재된다. **새 게임은 `↓=가드 / X=필살기`로 명확히 분리**하고 화면에도 그대로 표시한다.

### 3.1 게임 화면

```text
┌────────────────────────────────────────────────────────────────┐
│ ♥ ♥ ♥    SCORE 000012450   COMBO x24       NEXT: BURJ KHALIFA │  HUD
│                        STAGE 09 / HARD                        │
│                                                                │
│                      ↓ FALLING ↓                               │
│                  ┌─────┬─────┬─────┐                           │
│                  │ HP1 │ HP2 │ HP3 │ ← 구조별 약점 시각화       │
│                  ├─────┼─────┼─────┤                           │
│                  │ HP3 │ HP1 │ HP2 │                           │
│                  ├─────┼─────┼─────┤                           │
│                  │ HP2 │ HP1 │ HP3 │ ← 현재 최하층              │
│                  └─────┴─────┴─────┘                           │
│                         ⚔                                      │  플레이어
│ ───────────────────────── GROUND ───────────────────────────── │
│ GUARD  ███████░░░ 72%                SPECIAL ████████░░ 80%  │  하단 상태창
└────────────────────────────────────────────────────────────────┘
              ← → 이동, ↑ 점프, ↓ 가드, Z 공격, X 필살기
```

> 위 ASCII 도식은 **판정 규칙 예시**이며 실제 UI에서는 HP 1/2/3이라는 큰 문자를 건물에 매번 표시하지 않는다. 낡은 균열·보통 재질·강화된 구조 등 재질별 시각적 단서로 구분하고, 튜토리얼이나 접근성 모드에서만 HP 숫자를 노출한다.

**HUD 표시사항:** 목숨 3개, 현재 점수, 최고 점수, 콤보, 현재 난이도, 현재 건물 이름, 가드 게이지, 필살기 게이지, 일시정지·음소거. 모바일에서는 UI 크기/배치만 재구성하되 필수 정보는 숨기지 않는다.

### 3.2 화면 상태

1. `BOOT`: 저장된 설정·로컬 에셋 준비. 진입 즉시 스플래시. 에셋 실패 시 빠른 대체 렌더링.
2. `TITLE`: 시작, 조작법, 음향 on/off. 첫 진입에서 조작법 1회만 축약 제시.
3. `COUNTDOWN`: 3→2→1 짧은 시작 연출, 입력 중복 방지.
4. `PLAYING`: 실제 실시간 게임.
5. `HIT_FREEZE`: 피격 0.12초 연출용(논리적으로 중복 피해 금지); 복귀 혹은 게임 오버.
6. `PAUSED`: 모든 게임 시간 정지, 입력·물리·콤보 타이머 정지.
7. `GAME_OVER`: 점수, 파괴 건물, 최고 콤보, 최고 점수 갱신 여부, 재시작.
8. `SPECIAL_CUTIN`: 0.45~0.8초 필살기 연출 및 건물 파괴 판정. 연출 중 무적.
9. `WAVE_TRANSITION`: 0.3~0.6초 건물 이름 등장 후 다음 건물 낙하.

모든 상태는 명시적 유한상태기계로 구현한다. 상태가 바뀔 때 중복 RAF, 키 반복, 사운드, 타이머가 쌓이지 않도록 한다.

## 4. 입력 및 캐릭터 [MUST]

### 4.1 키 매핑

| 기능 | 데스크톱 | 모바일 | 판정 |
|---|---|---|---|
| 왼쪽 | `←` / `A` | 왼쪽 버튼 또는 레인 탭 | 레인 -1 |
| 오른쪽 | `→` / `D` | 오른쪽 버튼 또는 레인 탭 | 레인 +1 |
| 점프 | `↑` / `W` / `Space` | 점프 버튼 | 지면에서 점프 |
| 가드 | `↓` / `S` | 가드 버튼(누른 동안) | 지상/공중 자동 구분 |
| 공격 | `Z` / `J` | 공격 버튼 | 반복 가능한 칼 베기 |
| 필살기 | `X` / `K` | 필살기 버튼 | 게이지 100일 때 발동 |
| 일시정지 | `Esc` / `P` | 일시정지 | PAUSED 토글 |
| 음소거 | `M` | 음소거 버튼 | 즉시 설정 적용 |

- 키보드 기본 스크롤 동작은 게임이 포커스를 가질 때 `preventDefault`한다.
- `keydown`/`keyup`을 추적하며, 윈도우 포커스 상실·화면 숨김 시 눌림 상태를 해제하고 자동 일시정지.
- **연속 공격:** `Z` 누르고 있으면 내부 공격 쿨다운 간격마다 자동 발동. 빠르게 눌러도 물리 프레임당 중복 히트 금지.
- **이동:** 캐릭터는 지정된 3개의 레인 중심에만 위치. 꾹 누르기는 130ms 간격 레인 이동, 개별 눌림 즉시 반응.
- 동시 키 입력 허용: 이동+공격, 점프+공격, 점프+가드.
- 모바일 버튼은 좌우/점프/가드/공격/필살기가 동시에 눌리도록 `pointerdown`, `pointerup`, `pointercancel`로 처리. 페이지 스크롤이 게임을 방해하지 않아야 한다.

### 4.2 캐릭터 이동 및 점프(초기 밸런스 값)

| 파라미터 | 초깃값 |
|---|---:|
| 레인 이동 애니메이션 | 75ms ease-out |
| 연속 레인 이동 최소 간격 | 130ms |
| 공격 간격 | 100ms (초당 최대 10히트) |
| 공격 애니메이션 | 90ms, **첫 프레임 판정** |
| 점프 초기 수직속도 | -430 world units/s |
| 중력 | +1,250 world units/s² |
| 전체 점프 체공시간 | 약 0.69s |
| 재점프 조건 | 지면 접촉 후 (기본 이중점프 없음) |

- 월드 좌표는 **세로 600 world units** 기준이며, 모든 물리값은 실제 창 크기가 아니라 월드 단위 사용.
- 캐릭터 높이·레인은 표시용이고 공격 판정은 `activeFloor`의 현재 레인에만 적용. 공중에서 윗층을 관통해 선행 파괴하지 않는다.
- **공격의 시각적 칼 궤적**은 큰 원호·빛 효과로 표현하되 실제 판정과 분리해 결정적으로 구현한다.
- 플레이어 이동 애니메이션 중 공격하면 **이동 시작 시점이 아니라 공격 순간의 논리 레인**에 판정한다.

## 5. 건물 데이터·층 파괴 시스템 [MUST, 최우선]

### 5.1 핵심 데이터 모델

```ts
// TypeScript 같은 문법으로 데이터 구조를 설명한 것. 구현은 일반 JavaScript로 가능.
type Lane = 0 | 1 | 2;
type HP = 0 | 1 | 2 | 3;

type Floor = {
  id: string;              // 중복 없는 ID
  ordinal: number;         // 실제 건물의 층수가 아니라 이 게임의 논리 층 번호
  hp: [HP, HP, HP];        // 해당 레인별 '현재 남은 HP'
  initialHp: [1 | 2 | 3, 1 | 2 | 3, 1 | 2 | 3];
  visualSliceId: string;   // 랜드마크 별 시각적 단면
  height: number;          // 건물 생성 시 결정, 파괴할 때 바뀌지 않음
  breakable: boolean;     // MVP에서는 true
};

type FallingBuilding = {
  id: string;
  landmarkId: string;
  floors: Floor[];         // index 0 = 현재 가장 아래층
  bottomY: number;        // 현재 최하층 하단의 월드 Y 좌표
  velocityY: number;      // 아래로 향하는 속도 (+)
  tier: number;
  specialProfile?: string;
  defeated: boolean;
};
```

### 5.2 필수 파괴 알고리즘

1. 공격 입력 → 공격 쿨다운 검사 → 현재 건물이 있는지 검사 → `floors[0]`(현 최하층)을 선택.
2. 캐릭터의 논리 레인 `lane`에 대응하는 `floor.hp[lane]`만 정확히 **1 감소**.
3. HP가 2→1 등으로 바뀌면 **그 레인 외벽만** 금·균열·스크래치가 변화한다.
4. **어느 한 레인의 HP가 0이 되는 순간**, 다른 레인의 HP가 남아 있어도 **현재 층 전체가 파괴**된다.
5. 한 층 파괴는 정확히 한 번만 처리하며 `floors.shift()`로 제거.
6. 파괴된 층 높이 `h`만큼 `building.bottomY -= h` 하여 남은 건물이 순간적으로 위쪽으로 비켜나는 효과를 준다. 이후 다시 낙하한다.
7. 화면에는 현재 층 파편, 창문 유리, 먼지, 층 단위 분리된 건물 조각이 나타나야 한다.
8. `floors.length === 0`이면 현재 건물을 완전히 제거하고, 점수 보너스, 파괴 건물 수 증가, 다음 웨이브로 진행.
9. 파괴 처리 직후 1프레임에 추가 공격이 들어오더라도 이전 층에 다시 점수/게이지를 주지 않는다.
10. 특수한 지붕·탑·기둥 모양의 건물도 판정 시스템은 동일하게 `Floors + 3 lanes`로 처리한다.

```js
function attackCurrentFloor(state) {
  if (state.phase !== 'PLAYING' || !canAttack(state)) return;
  const building = state.building;
  if (!building || building.defeated) return;

  consumeAttackCooldown(state);
  const floor = building.floors[0];
  if (!floor) return;
  const lane = state.player.lane;
  if (floor.hp[lane] <= 0) return;

  floor.hp[lane] -= 1;
  onSuccessfulHit(state, floor, lane); // 점수/콤보/특수 게이지 1회만

  if (floor.hp[lane] === 0) {
    // 반드시 '해당 레인만'이 아니라 '현재 층 전체'를 제거한다.
    building.floors.shift();
    building.bottomY -= getFloorHeight(floor, building);
    onFloorDestroyed(state, floor);
    if (building.floors.length === 0) onBuildingDestroyed(state, building);
  }
}
```

**금지되는 잘못된 구현:** 전체 건물 HP 막대 하나만 깎기 / 서로 다른 3레인 HP를 모두 0으로 만들어야 1층이 부서지기 / 층을 지우지 않고 파티클만 뿌리기 / 건물이 한 장의 정적 이미지로 남아 파괴 후에도 원래 높이로 보이기.

### 5.3 약점 등급

| 등급 | HP | 시각적 표현 | 기본 배분 |
|---|---:|---|---|
| WEAK | 1 | 금 간 콘크리트/균열/느슨한 골조, 밝은 힌트 | 1타에 층 파괴 |
| NORMAL | 2 | 보통 유리/벽면 | 2타 |
| HARD | 3 | 강화 구조, 금속/황금/석재 테두리 | 3타 |

- 시각적 층 높이 계산: `floorHeight = clamp(18, 36, 300 / logicalFloorCount)` world units로 시작하며 랜드마크 메타데이터의 `heightRatio`를 사용해 총높이 안에서 구간별 편차를 준다. 바뀐 층 높이는 `getFloorHeight`로 일관되게 반환해 파괴 순간 위치·렌더·충돌 모두 동일하게 반영한다. `floorHeight`를 프레임마다 재계산해 파괴 후 층 높이가 늘어나는 현상은 금지한다(생성 시 모든 층에 실제 pixel/world 높이를 저장).
- 각 층의 3레인마다 HP를 독립 생성한다.
- 가능한 경우 한 층에 적어도 1개의 상대적 약점이 존재하도록 만들어 레인 이동의 의미를 살린다.
- 약점 분포는 난이도별 가중 랜덤으로 생성하되, **한 층에서 좌·중·우 모두 HP 3이고 다음 층도 모두 HP 3인 패턴**은 극한 구간을 제외하고 금지.
- HP 숫자는 필수 HUD가 아니라 튜토리얼/옵션 표시. 기본은 건물 텍스처의 차이로 판단 가능하게 한다.
- 한 건물에서 약점이 항상 같은 레인에 생성되지 않도록 하며, 연속 3층 이상 동일 약점 레인이 반복될 확률을 낮춘다.

### 5.4 낙하·반동·지면 충돌

월드 높이 `H=600`을 기준으로 한다.

| 항목 | 초깃값 | 설명 |
|---|---:|---|
| 지면 위험선 | `groundY=530` | 캐릭터가 있는 지면 기준 |
| 건물 출현 지점 | `bottomY=85` | 건물 하단이 상단 화면 안쪽에 등장 |
| 기본 낙하속도 | `115 units/s` | 1단계 속도 |
| 일반 공격 반동 | `-7 units` | 공격 성공 시 건물 하단 Y를 위로 밀어냄 |
| 층 파괴 반동 | `-floorHeight` | 층 제거로 잔여 건물이 실제로 위로 짧아짐 |
| 낙하속도 상한 | `baseSpeed * difficultyMultiplier * 1.12` | 불필요한 무한 가속 방지 |
| 건물별 등장 공백 | 0.35~0.55초 | 다음 건물로 빠르게 전환 |

- 매 틱 `bottomY += velocityY * deltaSeconds`.
- 시간에 따른 낙하가속은 MVP에서 기본 0이며, 후반 엘리트 건물에만 `0~18 units/s²`까지 허용(별도 프로파일). 원작과 달리 기본적으로 진행 시 **웨이브별 속도 증가**를 사용한다.
- 공격 적중의 상향 반동은 층 제거를 포함한 모든 정상 타격에 적용한다.
- 충돌은 **현재 남아 있는 건물의 실제 bottomY**를 기준으로 한다. 화상 효과·파티클의 위치는 판정에 포함하지 않는다.
- 건물이 지면 위험선에 닿고 필살기 무적/성공한 가드 판정이 없으면 라이프를 정확히 **1 감소**.
- 한 충돌로 연속 2~3개의 라이프를 빼면 버그. 피격 시 기존 건물 제거 → 1.25초 무적 → 다음 건물 시작(신규 HTML판의 접근성 중심 조정).
- 피격 후 남은 목숨이 0이면 Game Over로 즉시 전환하고 새로운 건물을 생성하지 않는다.

## 6. 점프·가드 [MUST]

### 6.1 가드 종류 및 트레이드오프

| 구분 | 지상 가드 | 공중 가드 |
|---|---:|---:|
| 발동 조건 | 점프하지 않은 상태 | 플레이어가 점프 중 |
| 가드 게이지 1회 소비 | 30 | 18 |
| 유효 접촉 시 건물 밀기 | 위로 85 units | 위로 35 units |
| 접촉 후 낙하속도 배율 | 0.30 | 0.55 |
| 콤보 | **0으로 리셋** | **유지** |
| 이펙트 | 강한 지면 충격파 | 공중 칼 충격파 |

**판정 순서:** 필살기 무적 → 유효 가드 접촉 → 충돌 라이프 소모.

### 6.2 가드 상태 세부 규칙

- ↓/가드 버튼을 누르면 0.25초의 가드 윈도우 시작. 지속 누르면 `guardHeld` 유지; 방어 구간 동안 초당 12 게이지 소모.
- 실제로 건물이 위험선 근처(`bottomY >= groundY - 95`)이고 가드가 활성 상태일 때 가드 접촉을 발동. 가드 입력만으로 화면 밖 건물이 밀려서는 안 된다.
- 가드 접촉 후 최소 0.28초 쿨다운 적용. 같은 충돌 프레임에 가드가 여러 번 발동하지 않는다.
- 가드 게이지 `0..100`, 초기 100, 가드하지 않을 때 초당 +18 회복(가드 종료 후 0.25초부터). 가드 시작/유지 소비와 가드 접촉 시 추가 소비가 겹쳐 0 미만이 되지 않도록 clamp.
- 접촉 비용을 지불할 수 없으면 `GUARD BREAK` 효과만 발생하며 충돌을 막지 못한다. 화면에 게이지 부족을 명확히 표시.
- 지상 가드로 콤보가 끊기는 경우 수치가 즉시 0으로 보이고 콤보 타이머도 초기화.
- 공중 가드에서는 콤보가 유지되며 타이머를 0.45초 연장해 연속 공중 전투가 가능해야 한다.
- 가드는 **무적 버튼이 아니다**. 유효 접촉 타이밍과 남은 게이지가 필요하다.

### 6.3 점프가 게임플레이에 반드시 필요한 이유

- 공중 가드 보너스가 **콤보 유지**이므로 고득점을 위해 점프-공격-가드를 반복할 수 있다.
- 점프 중 공격은 정상적인 최하층 공격으로 간주한다.
- HUD 또는 짧은 튜토리얼에 `공중 가드는 콤보를 유지합니다` 문구를 넣는다.

## 7. 콤보, 점수, 필살기 [MUST]

### 7.1 콤보 규칙

- **건물에 실제 명중한 공격 1회마다 콤보 +1**.
- 단순 공중 베기/허공 공격은 콤보나 게이지를 증가시키지 않는다.
- 마지막 적중 후 **1.5초** 이내에 다음 적중하면 이어진다.
- 1.5초 초과, 피격, 지상 가드 시 콤보 0. 게임 일시정지 중에는 타이머가 흐르지 않는다.
- 공중 가드 성공 시 콤보 유지(타이머 0.45초 연장).
- 필살기는 콤보를 일단 유지하되, 필살기 사용 중 콤보 타이머 정지; 건물 파괴가 끝난 후 새로운 타이머 시작.
- 레벨 전환은 콤보가 유지될 수 있도록 하며 전환 연출 시간에는 콤보 타이머가 감소하지 않는다.

### 7.2 점수 공식(신규 게임 공식)

```text
hitScore        = 10 * comboMultiplier
floorClearScore = (100 + floor.ordinal * 5) * comboMultiplier
buildingBonus   = 500 + difficultyTier * 100 + originalFloorCount * 20
comboMultiplier = min(3.0, 1 + floor(combo / 5) * 0.25)
```

- 점수는 정수 반올림해 누적.
- 필살기로 남은 층을 제거하면 `floorClearScore * 0.65`를 층별 1회 지급하고, 건물 완파 보너스는 동일 지급. 필살기 파괴에서는 일반 적중 점수와 게이지 충전이 발생하지 않는다.
- 건물을 빠르게 부숴도 별도의 시간 보너스는 MVP에서 주지 않는다(빠른 조작은 점수·생존으로 보상받음).
- 파괴된 층을 다시 공격하거나 애니메이션이 재생돼도 점수 이중 지급 금지.
- 신규 최고 점수와 최대 콤보는 `localStorage`에 저장. 로컬 저장이 불가능해도 플레이는 계속되어야 한다.

### 7.3 필살기 규칙

| 항목 | 정의 |
|---|---|
| 게이지 범위 | 0~100 |
| 초기값 | 0 |
| 일반 명중 시 충전 | `7 + min(8, floor(combo / 8) * 2)` |
| 사용 가능 | 100일 때만 |
| 사용 시 | 현재 게이지 즉시 0, 연출 상태 진입 |
| 효과 | **현재 건물에 남아 있는 모든 층** 제거 |
| 무적 | 연출 시작부터 종료까지 |
| 재사용 | 게이지 다시 100이 되어야 가능 |
| UI | 가득 차면 화면 하단에 `SPECIAL READY` 점멸, 모바일 필살기 버튼 활성 |

필살기는 `X` 입력 첫 프레임에 즉시 인정하고 상태를 `SPECIAL_CUTIN`으로 전환한다. 0.45~0.8초 동안 캐릭터가 상공으로 솟구치고 수직 검광이 건물을 관통하며 남은 모든 층이 차례로 터지는 연출. **논리 판정은 사용 즉시** 완료 처리해 필살기 중 건물이 바닥에 닿아 라이프가 감소하지 않게 한다.

## 8. 난이도 상승: 구현 수치 완전 정의 [MUST]

**기준 = 이 판에서 완전히 파괴한 건물 수 `destroyedBuildings`**. 해당 값이 증가할 때마다 다음 건물 생성에 적용한다. 현재 건물이 내려오고 있는 중에는 난이도 데이터가 바뀌지 않는다.

| 파괴 건물 수 | Tier | 층수(논리 층) | 낙하 배율 | WEAK HP1 | NORMAL HP2 | HARD HP3 | 패턴 |
|---|---:|---:|---:|---:|---:|---:|---|
| 0~2 | 1 | 3~5 | 1.00 | 65% | 30% | 5% | 거의 모든 층에서 1타 약점 발견 |
| 3~5 | 2 | 4~7 | 1.20 | 50% | 38% | 12% | 한쪽 끝 약점, 이동 유도 |
| 6~9 | 3 | 6~9 | 1.40 | 35% | 45% | 20% | 3타 구조물 시작 |
| 10~14 | 4 | 8~12 | 1.70 | 25% | 45% | 30% | 약점 방향 급변, 속도 상승 |
| 15~19 | 5 | 10~15 | 2.00 | 20% | 40% | 40% | 강한 층 연속, 엘리트 증가 |
| 20+ | 6 | 12~20 | 최대 2.40 | 15% | 35% | 50% | 복합 레이아웃과 특수 파괴 구간 |

- 기본 속도 = `115 world units / sec`; 실제 속도 = `115 * tier.speedMultiplier`.
- Tier 6에서는 `2.0 + min(0.4, 0.05 * floor((destroyedBuildings-20)/3))`, 즉 20채 직후 2.0부터 증가하여 최대 2.4배로 제한해 진행 불가능한 폭주를 막는다. UI에는 **Tier 6 / EXTREME**로 표시.
- tier 1~5의 속도배율은 표에 정의된 값을 그대로 사용한다.
- 랜덤은 `seededRandom(runSeed, buildingIndex)` 사용해 재현 가능해야 한다.
- 한 층에 HP1이 최소 하나 등장할 확률 가이드: Tier1 100%, Tier2 90%, Tier3 70%, Tier4 45%, Tier5 30%, Tier6 20%. 이 확률이 성립한 경우 생성된 3레인의 HP 중 한 곳을 HP1로 보정한다.
- 약점 레인 3개 층 연속 동일 패턴은 Tier1~3에서 반드시 회피, Tier4~6에서는 낮은 확률로 허용.
- **최근 2개 건물과 동일한 랜드마크를 다시 뽑지 않는다.** 난이도는 랜드마크의 실제 층수에 의존하지 않는다.
- 5·10·15·20...번째 낙하 건물은 `ELITE` 변형(특수 테두리·효과), 그러나 전체 메커니즘은 층 파괴 규칙과 동일. 별도의 비합리적 원킬 전용 적은 만들지 않는다.

### 8.1 너무 어려운/너무 쉬운 구간을 판별하는 플레이테스트 목표

- 첫 3채: 게임을 처음 접한 사람도 약점과 공격을 익히면 2채 이상 파괴 가능.
- 6~9채: 빠른 레인 변경 또는 가드를 생각하게 되는 수준.
- 10~14채: 필살기 또는 점프 가드 활용 여부가 생존에 영향을 줌.
- 20채 이후: 숙련자의 빠른 대응 요구. 3초 이상의 긴 정적 상태 금지.
- 보정 시 **오직 `balance.js`의 값만** 수정할 수 있어야 하며 로직에 수치를 하드코딩하지 않는다.

## 9. 세계 유명 건물 콘텐츠 [MUST]

### 9.1 유명 건물에서 ‘Floor’를 정의하는 방법

- 실제 건축물의 역사적/법적 층수는 게임의 파괴 단위와 동일하지 않다.
- `logicalFloor`는 **게임플레이용 독립 파괴 세그먼트**다. 예: 경복궁은 지붕/기둥/기단 등을 3~10 구간으로 나눈다.
- 시각적 파괴 세그먼트는 건물마다 비정형 `path`, `polygon`, `mask`로 표현할 수 있다.
- 판정용 데이터는 어디까지나 세그먼트의 좌/중/우 HP 3개. 비정형 실루엣에서도 키보드 레인별 HP 판정의 난이도가 변하지 않아야 한다.
- **외관(아트)과 충돌/층수(로직) 분리**. 실제 건물 높이를 그대로 재현하려다가 101층을 하나하나 공격하게 만들지 않는다.
- 각 건물은 `silhouette`, `segmentSlices`, `hitMaterialStyles`, `debrisPalette`, `displayName` 메타데이터를 가진다.
- 트윈 타워는 한 세그먼트 안에 2개의 시각적 구조가 있어도, 1개 논리 세그먼트로 동작할 수 있다.

### 9.2 랜드마크 표시와 게임 매너

- 현실의 건축물을 활용하는 **명백히 허구적·만화적 파괴 게임**으로 표시한다.
- 재난 피해자, 시민, 실존 인물 등은 등장시키지 않는다. 실사 재난 사고처럼 오인할 수 있는 뉴스 스타일보다 과장된 아케이드 스타일 사용.
- 각 랜드마크별 상표·저작권·건물 이미지 라이선스를 점검한다. 특히 상업 배포 시 외부 상표 로고와 실사 사진을 그대로 도용하지 않는다.
- 실제 모델/사진을 무단 스크래핑하지 않는다. 원본성 있는 새 에셋을 만든다.

## 10. xAI / Grok Imagine 에셋 제작 파이프라인 [MUST]

### 10.1 절대적 아키텍처 제한

```text
[개발자의 머신 / 개발 단계에만]
   XAI_API_KEY 환경변수
       │
       ▼
 scripts/generate-assets.mjs ──HTTPS──▶ xAI Image Generation API
       │                           (오직 이 스크립트에서 호출)
       ▼
 public/assets/generated/*.png
 public/assets/processed/*.webp
 public/assets/manifest.json
       │
       ▼
[배포]
 index.html + 정적 JS/CSS + 완성된 정적 이미지
       │
       ▼
[이용자의 브라우저]
 requestAnimationFrame + Canvas 2D + localStorage
 **0 API CALLS / 0 AI INFERENCE / NO KEY / NO BACKEND**
```

**엄격 금지:** 브라우저 안에 `XAI_API_KEY` 삽입 / 공개 `VITE_XAI_API_KEY` / 플레이 중 Grok 이미지 생성 / 건물 등장 시 AI 요청 / 타격마다 이미지 생성 / 런타임 AI fallback / 외부 임시 이미지 URL을 핫링크하여 게임 의존성 생성.

### 10.2 API 사양과 실행

공식 문서에서 확인한 현재 이미지 생성 엔드포인트:

- Base URL: `https://api.x.ai/v1`
- Endpoint: `POST /images/generations`
- Model: `grok-imagine-image-2.0`
- Auth: `Authorization: Bearer $XAI_API_KEY`
- 요청: `prompt`, `model`, 필요 시 `aspect_ratio`, `resolution`, `quality`, `response_format=b64_json`.
- URL 반환 방식일 경우 결과 URL은 임시이므로 **즉시 다운로드하고 로컬 저장**해야 한다.
- API가 변경되면 공식 문서를 확인해 *개발용 스크립트만* 수정한다. 게임 런타임은 영향을 받지 않아야 한다.

```bash
# 개발 머신에서만 실행하는 예시 (게임에서 호출 금지)
curl -X POST https://api.x.ai/v1/images/generations \
  -H "Authorization: Bearer $XAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "grok-imagine-image-2.0",
    "prompt": "Original 2D arcade game asset, recognizable silhouette of Lotte World Tower, clean isolated building, front orthographic elevation, plain high-contrast background, no people, no text, no logos, no watermark, centered, consistent bright stylized game art, high detail",
    "aspect_ratio": "2:3",
    "resolution": "2k",
    "quality": "medium",
    "response_format": "b64_json",
    "n": 1
  }'
```

키는 `.env.local` 또는 셸 환경변수에서만 읽고, 깃에 업로드하지 않는다. 게임 프론트엔드 코드에서 `process.env.XAI_API_KEY`와 유사한 코드를 읽지 않는다.

### 10.3 생성해야 할 에셋 목록

| 종류 | 최소 결과물 | 생성 방법 | 게임 중 생성 여부 |
|---|---|---|---|
| 랜드마크 | 최소 8개, 목표 12개 정면 일러스트 | xAI 개발 단계 | 절대 금지 |
| 배경 | 도시 주간, 저녁 노을, 야간 3개 | xAI 개발 단계 | 절대 금지 |
| 캐릭터 | 기본 검객 캐릭터 1종, 공격·점프·가드 참조 시트 | xAI 개발 단계 + 개발자 리깅/추가 프레임 | 절대 금지 |
| 필살기 컷인 | 오리지널 검광/타이포그래피 배경 1개 | xAI 개발 단계 | 절대 금지 |
| 파편 질감 | 유리·돌·철골·기와 4개 | xAI 또는 오리지널 procedural | 절대 금지 |
| HUD 아이콘 | 하트·칼·방패·번개 | SVG/Canvas 직접 제작 | 절대 금지 |

- 개발 단계에서 생성한 정적 에셋은 리포지토리/정적 빌드에 포함한다.
- 디자인은 **2D 아케이드, 스타일화된 도시, 명료한 윤곽선, 선명한 구조 실루엣**으로 통일한다.
- 애니메이션은 생성 이미지 프레임을 네트워크로 불러오는 방식이 아니라 Canvas 2D의 위치·각도·스케일·opacity·파티클로 만든다.
- 프롬프트 및 생성 옵션을 파일로 보존해 재생성 가능하게 한다.

### 10.4 가장 중요한 문제: AI 이미지는 층별 파괴 데이터가 아니다

한 장짜리 이미지에서 임의로 **건물 한 층을 자동으로 지우는 것**만으로는 파괴 시스템이 성립하지 않는다. 반드시 아래를 구현한다.

1. `fullBuilding` 원본을 **정면 이미지**로 생성한다.
2. 개발 단계에서 배경 제거·투명화·원근 정리, 건물별 수동 또는 절차적 실루엣 마스크를 작성한다.
3. 랜드마크별 `segments`에 필요한 시각적 단면 이미지(또는 이미지 crop UV + polygon mask)를 지정한다.
4. 각 세그먼트는 파괴할 때 다른 세그먼트와 **독립적으로 숨기거나 날릴 수** 있어야 한다.
5. 세그먼트 파괴 후 남은 모든 상단 시각 조각은 논리 `building.bottomY`에 맞게 재배치된다.
6. 단순 직사각형 세로 자르기를 모든 건물에 동일 적용하는 방법은 금지. 경복궁 지붕·에펠탑 철골·오페라 하우스 곡면은 개별 마스크가 필요하다.
7. AI 결과에 투명 배경이 제대로 나오지 않으면 오프라인 이미지 전처리로 크로마키/마스크를 적용한다. 브라우저에서 배경을 실시간 제거하지 않는다.
8. 랜드마크의 모양이 깨지는 경우 *우선 인지 가능한 Canvas/SVG 수작업 실루엣을 이용한 fallback*으로 렌더링해 핵심 파괴 게임이 멈추지 않게 한다.

권장 메타데이터:

```json
{
  "id": "gyeongbokgung",
  "displayNameKo": "경복궁",
  "displayNameEn": "Gyeongbokgung Palace",
  "asset": "/assets/processed/gyeongbokgung.webp",
  "shapeType": "custom-segments",
  "segmentTemplate": [
    {"key":"base","heightRatio":0.26,"polygon":"base-mask"},
    {"key":"columns","heightRatio":0.36,"polygon":"wooden-columns"},
    {"key":"roof","heightRatio":0.38,"polygon":"curved-tile-roof"}
  ],
  "debrisPalette": ["#5b382a", "#d6c0a6", "#34404b"],
  "damageMaterials": ["cracked","standard","reinforced"]
}
```

**주의:** `segmentTemplate`는 시각적 분포 비율의 가이드일 뿐이다. 8~20 논리 층을 가진 웨이브에서는 세그먼트를 반복·세분할 수 있지만 외형의 구분 가능성을 잃으면 안 된다.

### 10.5 에셋 비용·실패 처리·검수

- 에셋 생성 스크립트는 `--only=...`, `--limit=N`, `--dry-run` 지원.
- 이미 존재하는 파일은 기본적으로 재호출하지 않으며 `--force`일 때만 재생성.
- 생성 결과와 `model`, `promptHash`, `createdAt`, `filename`, `status`, `callCount`를 manifest에 기록.
- 실패 시 재시도 최대 2회(점진적 백오프), 무한 루프 방지. 한 번 실행에서 최대 25회 외부 생성 호출 제한(옵션으로 재설정 가능).
- 에셋은 일반적으로 WebP로 전처리·최적화; 생성 원본은 필요하면 개발용 폴더에 보존.
- 플레이어 화면의 실패 에셋은 **Canvas/SVG fallback**으로만 표시하며 외부 AI 요청은 하지 않는다.
- 에셋 품질 검사: 실루엣 인지 가능한가, 화면에서 충분히 큰가, 얼굴/문자/워터마크가 섞이지 않았는가, 층별 조각의 투명도가 맞는가, 파괴 후 유령 이미지가 남지 않는가.

## 11. 그래픽·애니메이션·물리 [MUST]

### 11.1 렌더링

- HTML5 Canvas 2D 사용. 데스크톱 60 FPS 목표, 모바일 30 FPS 이하에서도 판정 속도 유지.
- `requestAnimationFrame` + 고정 길이 물리 스텝(`1/60s`) accumulator 권장. `deltaTime` clamp 최대 0.05초로 백그라운드 복귀 폭주 방지.
- `devicePixelRatio`는 상한 2.0으로 설정해 모바일 메모리 폭증 방지.
- **월드 높이 600단위**를 유지하고 실제 Canvas 크기에 대응해 월드 너비를 화면비로 계산한다. 중앙 3레인 x를 동적으로 산출.
- PC는 가로 화면 기반 구성, 모바일 세로 화면은 `worldWidth`에 맞춰 건물·레인 폭 축소하고 조작패드를 하단 별도 영역에 배치한다.
- UI는 HTML/CSS 오버레이로 그리고 게임 오브젝트만 Canvas에서 그려도 무방. HUD 문자 해상도·접근성 유지.

### 11.2 파괴 애니메이션

**직접 구현해야 할 구체 연출**

1. 일반 타격: 0.05초 검광, 타격 지점 3~8개 스파크, 표면 균열 변화, 미세 화면 흔들림.
2. 약점 HP0/층 전체 파괴: 시각적 층이 **즉시 사라짐** → 6~16개 파편 파티클이 속도/회전/중력 적용 → 먼지/유리 조각 → 짧은 충격파.
3. 전체 파괴: 카메라 4~10px 범위 짧은 흔들림, 파편 폭발, 건물 이름·파괴 점수 팝업.
4. 콤보 10/25/50/100: 크기·글자 스케일/짧은 글로우 단계적 증가. 화면 가림 금지.
5. 필살기: 0.45~0.8초, 검객 점프, 화면 세로 검광, 연속 층 붕괴, 0.08초 정도 hit-stop, 색 플래시, 사운드.
6. 목숨 소모: 카메라 펀치, 캐릭터 짧은 붉은 틴트, ♥ 감소, 1.25초 무적 점멸.

**파괴는 물리 엔진으로 건물을 통째로 부수는 것이 아니라 게임 로직의 층 제거 + 가벼운 입자 물리**다. 첫 버전에 Matter.js 같은 무거운 전체 rigid body 시뮬레이션을 강제하지 않는다. 대신 파편은 질량감 있게 떨어지고 회전해 보여야 한다.

### 11.3 입자 물리 초기값

```js
fragment = {
  x, y,
  vx: random(-150, 150),
  vy: random(-300, -70),
  gravity: 850,     // units/s²
  rotationSpeed: random(-9, 9),
  life: 0.45 + random(0, 0.45),
  drag: 0.985
};
```

- 파편은 좌표·중력·회전값이 실제로 매 틱 변해야 한다. 멈춘 이미지에 페이드만 주지 않는다.
- 오브젝트 풀 사용. 화면에 파편이 250개 이상 쌓이면 가장 오래된 파편부터 정리. 픽셀 성능을 보장한다.
- `prefers-reduced-motion` 감지 시 화면 흔들림/과한 플래시 감소. 광과민 유발하는 연속 고속 전체 화면 번쩍임 금지.

### 11.4 배경과 사운드

- 배경은 지역 랜드마크에 따라 낮/노을/밤 중 하나로 변경. 건물보다 시각적으로 덜 복잡하게.
- 미세 구름 이동·도시 패럴랙스 허용하지만 프레임 성능을 해치지 않는다.
- 음악은 별도 라이선스 확인된 파일 또는 직접 제작. 무료 음원이라고 무조건 상업 사용 가능한 것은 아님.
- 타격·층 파괴·가드·필살기·피격 각각 다른 효과음. 에셋이 없으면 Web Audio의 간단한 합성 효과음 허용.
- 모든 사운드는 사용자 제스처 후에만 재생. 음소거/볼륨 설정 보존.

## 12. 세계관 차별화·후반 특수 콘텐츠

### 12.1 MVP 필수: 엘리트 건물 [MUST]

- 매 5번째 건물은 `ELITE` 표시 및 해당 랜드마크에 어울리는 특징적인 조명/파편/간단한 지면 흔들림.
- 추가 HP를 무턱대고 늘리지 않고, 난이도표 안에서 가능한 층수 상단과 약점 분포를 사용.
- 엘리트라도 **HP 1/2/3 → 현재 층 전체 파괴** 규칙은 절대 변경하지 않는다.
- 엘리트 완파 시 `ELITE CLEAR` 스코어 팝업(추가 +300점), 오작동 없이 다음 웨이브.

### 12.2 고전 원작의 제2막에서 영감 받은 확장 [LATER]

MVP 본편은 유명 랜드마크 엔드리스 모드로 **처음부터 끝까지 플레이 가능**해야 한다. 다음은 본편이 완성된 뒤 추가할 별도 `CHAOS ACT` 모드의 **독립 명세**다. 원작의 오브젝트와 연출을 그대로 베끼지 말고 새로운 아트로 구현한다.

| 확장 대상 | 예시 테마 | 메커니즘 |
|---|---|---|
| 거대한 석상 | 석조 수호상 | 논리 6층·각 레인 HP5, 빠른 낙하·필살기 적극 활용 |
| 초고층 비석 | 고대 모놀리스 | 논리 20~30층 중 다수 HP1 구간 + HP10 보스 구간(확장 HP 타입 필요) |
| 번개 | 네온 번개 | 좌/중/우 예고 → 순간 강하, 타이밍 공격 회피/상쇄. 가드로 방어 불가 |
| 운석 | 하늘에서 떨어지는 암석 | 레인 지정 낙하. 파괴하지 않으면 지면에 남아 공간 점유 |
| 달/천체 보스 | 미래형 달 요새 | 돌진·낙뢰·투사체·특수 3레인 약점 패턴 |
| 엔드리스 | 세계 랜드마크 러시 | 제한 없는 웨이브, 최고 점수 경쟁 |

- **MVP에 HP 5/10/20, 번개·달 보스까지 억지로 끼워 넣지 않는다.** 별도 플러그형 `Hazard`, `BossPhase` 인터페이스를 설계해 추후 확장.
- 원작에서는 9,999,999점에서 제2막이 열리는 것으로 알려져 있으나 새 HTML판의 점수 배율로 그 조건을 그대로 강제하면 비현실적인 플레이 시간이 생긴다. **본편을 가로막는 숨은 해금 조건으로 적용하지 않는다.** 추후 별도의 도전과제에 원작의 숫자를 오마주할 수 있다.

## 14. 핵심 알고리즘 및 구현 세부 순서

### 14.1 고정 스텝 업데이트

```js
function tickGame(state, dt) {
  if (state.phase !== 'PLAYING') return;

  updatePlayerMovement(state, dt);
  updateJumpPhysics(state, dt);
  updateGuardHoldAndRegen(state, dt);
  handleRepeatAttack(state, dt);
  updateComboTimeout(state, dt);
  updateFallingBuilding(state, dt);

  // 동시에 충족되면 필살기 > 가드 > 라이프 차감 순서
  resolveBuildingContact(state);
  updateParticlePhysics(state, dt);
  updateHUDState(state);
}
```

- 프레임당 한 번의 판정만 나가도록 `lastAttackAt`, `lastGuardAt`, `lastContactFrame`, `building.defeated` 사용.
- 모든 이벤트 핸들러가 직접 game state를 여기저기 수정하지 않게 하고 `InputQueue` 또는 `state.intent`를 통해 일관된 규칙에 따라 처리.
- 재시작 후 `requestAnimationFrame` 실행 개수가 하나여야 한다.

### 14.2 건물 생성 절차

```text
spawnNextBuilding()
  1. destroyedBuildings로 difficultyTier 선택
  2. 12개 landmark 후보에서 최근 2개 제외하고 1개 선택
  3. tier 표에서 floorsCount 랜덤 선택
  4. 5의 배수 웨이브면 elite=true
  5. 층수만큼 HP 배열 생성 및 약점 분포 보정
  6. landmark segmentTemplate을 층수에 매핑
  7. bottomY=85, velocityY=115*multiplier
  8. 화면에 나라/건물명 0.4초 전환 후 PLAYING
```

다음 건물로 넘어갈 때 이전 건물의 히트박스·이펙트 소유관계·타이머가 남아 새 건물에 영향을 주지 않도록 한다. 파편은 기존 건물의 파티클로 잠시 남을 수 있으나 충돌에는 관여하지 않는다.

### 14.3 화면 리사이즈

- `resize`·디바이스 회전 시 기존 `player.lane`, 점수, HP, `building.bottomY` 월드 좌표를 그대로 유지한다.
- 화면 크기에 따라 **픽셀 위치만** 다시 산출한다. 리사이즈 때문에 건물이 즉시 바닥에 충돌하거나 새로 생성되면 버그.
- 타격 판정은 Canvas 픽셀을 테스트하는 것이 아니라 논리 상태를 테스트한다.

### 14.4 입력 버퍼와 공격 감각

- 공격 `keydown` 발생 프레임에 판정하고 100ms 쿨다운 동안 입력은 무시하거나 마지막 1개만 버퍼링(버퍼 ≤80ms).
- 캔버스 렌더 FPS가 30으로 낮아도 100ms 쿨다운을 유지한다. 60FPS 기기에만 유리한 게임이 되어선 안 된다.
- `keydown` 브라우저 반복 속도에 종속하지 않고 내부 시간으로 제어.
- 필살기 키 길게 누르면 100게이지 도달 즉시 자동 발동하지 않는다. **새 keydown/pointerdown 엣지**가 있어야 사용한다.

## 15. 튜토리얼 및 진입 경험 [MUST]

처음 시작할 때 5초 넘는 긴 튜토리얼 금지. **게임을 하면서** 아래 힌트를 최대 3개 순차 노출하고 자동 해제:

1. 첫 건물 등장: `← → 움직여 금이 간 곳을 공격하세요!` (1.8초)

- 화면 하단에는 언제든 간단한 키 안내를 볼 수 있게 한다.
- 재방문 시 튜토리얼 자동 숨김. 설정에서 다시 보기 가능.
- 게임 오버 후 바로 `다시 시작` 버튼이 가장 눈에 띄어야 한다.

### 16.2 체감 QA 시나리오

**QA-A. 약점 파괴**: 건물 가장 아래층에서 HP 1 균열 레인 선택 → Z 한 번. **한 레인만 사라지는 것이 아니라 건물의 그 층 전체가 동시에 폭발/삭제**되어야 한다.

**QA-B. 가드 차이**: 콤보 12 달성 → 지상 가드 성공 → 콤보 0. 다시 콤보 12 → 점프한 상태에서 공중 가드 성공 → 콤보 12 유지.

**QA-C. 필살기**: HP 3 구간이 많이 남은 건물에서 100% 충전 후 X → 멋진 연출 + 현재 건물 즉시 완파 + 생명 감소 없음 + 다음 건물 등장.

**QA-D. 난이도**: 디버그 테스트에서 `destroyedBuildings=0/3/6/10/15/20` 값을 주입해 층수, 속도, HP 가중치를 실측 비교. 차이를 감지할 수 있어야 한다.

**QA-E. 손맛**: 공격 키를 누르는 순간 검광, HP 변화, 타격음이 일치. 플레이 중 입력 후 **100ms 이상 늦게 반응하는 듯한 느낌이 없어야 함**.

**QA-F. AI 없는 게임**: 개발용 `.env.local` 제거, 브라우저 네트워크 오프라인 전환(초기 에셋 로딩 후) → 계속 정상적으로 공격/점프/파괴/게임오버가 이루어져야 한다.

**QA-G. 모바일**: 360×740 화면에서 버튼 6개 이상 제어 가능, 동시에 공격·이동·점프·가드 입력 가능. 화면 스크롤 및 브라우저 뒤로가기 간섭 최소화.

## 19. 마지막 승인 체크리스트(이 항목 미통과 시 완료 아님)

- [ ] 빠른 연속 공격이 실제로 가능하다.
- [ ] 3레인마다 내구도 1/2/3이 다르게 생성된다.
- [ ] **한 레인을 한 번 파괴하면 현재 층 전체가 사라진다.**
- [ ] 아래층이 없어지면 윗부분만 남아서 자연스럽게 떨어진다.
- [ ] 건물 파괴 수가 누적될수록 속도·층수·내구도 비율이 함께 어려워진다.
- [ ] 지상 가드와 공중 가드의 물리·콤보 결과가 다르다.
- [ ] 필살기 게이지를 공격으로 충전하고 건물 전체를 실제 파괴한다.
- [ ] 목숨이 3개에서 시작하고 충돌로 1개씩 줄어 게임 오버가 발생한다.
- [ ] 게임 오버 후 재시작하면 상태가 깨끗하게 초기화된다.
- [ ] 경복궁·롯데월드타워·부르즈 할리파 등 8개 이상의 유명 건물을 인식할 수 있다.
- [ ] 건물별 조각이 해당 실루엣을 따라 파괴된다.
- [ ] 타격감·검광·파편 중력·사운드가 실제 로직과 동기화된다.
- [ ] PC와 모바일에서 조작이 가능하다.
- [ ] **런타임 AI API 요청 0건**, 공개된 xAI API 키 0건이다.
- [ ] 단일 페이지 HTML 앱으로 배포 가능하다.
